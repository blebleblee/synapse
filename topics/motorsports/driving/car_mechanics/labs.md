Automate batch processing of multi-session data using Python scripting. MoTeC i2 Pro exposes a COM automation interface permitting external applications to programmatically open log files, execute math channel calculations, and export CSV data. Write a Python script leveraging the win32com library to iterate through all qualifying session logs, extract key performance indicators (minimum apex speeds, maximum brake pressures, throttle application points), and aggregate results into a pandas DataFrame. Plot time-series evolution of these metrics across the session to detect driver learning curves or tire degradation effects. The script below demonstrates this workflow, assuming MoTeC i2 Pro is installed and registered as a COM server:

```python
import win32com.client
import pandas as pd
import numpy as np
import matplotlib.pyplot as plt
from pathlib import Path

# Initialize MoTeC i2 Pro COM interface
i2_pro = win32com.client.Dispatch("MoTeC.i2Application")

# Define telemetry log directory and target corner sector
log_directory = Path("C:/Telemetry/Qualifying_Session_DriverA/")
corner_sector_start = 1200.0  # Track Distance in meters
corner_sector_end = 1350.0

# Initialize results storage
results = []

# Iterate through all LD files in directory
for log_file in sorted(log_directory.glob("*.ld")):
    # Open telemetry log
    i2_pro.OpenLog(str(log_file))
    workbook = i2_pro.ActiveWorkbook
    
    # Access required channels
    speed_channel = workbook.Channels("GPS Speed")
    brake_channel = workbook.Channels("Brake Pressure")
    track_distance = workbook.Channels("Track Distance")
    
    # Extract data arrays
    track_dist_array = np.array([track_distance.Values(i) for i in range(track_distance.DataCount)])
    speed_array = np.array([speed_channel.Values(i) for i in range(speed_channel.DataCount)])
    brake_array = np.array([brake_channel.Values(i) for i in range(brake_channel.DataCount)])
    
    # Filter data to corner sector
    sector_mask = (track_dist_array >= corner_sector_start) & (track_dist_array <= corner_sector_end)
    sector_speeds = speed_array[sector_mask]
    sector_brakes = brake_array[sector_mask]
    
    # Compute metrics
    min_apex_speed = np.min(sector_speeds)
    max_brake_pressure = np.max(sector_brakes)
    
    # Extract lap metadata
    lap_time = workbook.LapTime
    lap_number = workbook.LapNumber
    
    # Store results
    results.append({
        'Log File': log_file.name,
        'Lap Number': lap_number,
        'Lap Time': lap_time,
        'Min Apex Speed': min_apex_speed,
        'Max Brake Pressure': max_brake_pressure
    })
    
    # Close log
    i2_pro.CloseLog()

# Convert to DataFrame
df = pd.DataFrame(results)

# Compute lap time evolution and apex speed trend
df['Lap Time Seconds'] = df['Lap Number']  # Assuming sequential lap numbering
fig, axes = plt.subplots(2, 1, figsize=(12, 8))

axes[0].plot(df['Lap Number'], df['Lap Time'], marker='o', color='blue', linewidth=2)
axes[0].set_xlabel('Lap Number', fontsize=12)
axes[0].set_ylabel('Lap Time (s)', fontsize=12)
axes[0].set_title('Lap Time Evolution - Driver A Qualifying', fontsize=14, fontweight='bold')
axes[0].grid(True, alpha=0.3)

axes[1].plot(df['Lap Number'], df['Min Apex Speed'], marker='s', color='red', linewidth=2)
axes[1].set_xlabel('Lap Number', fontsize=12)
axes[1].set_ylabel('Minimum Apex Speed (km/h)', fontsize=12)
axes[1].set_title('Turn 7 Apex Speed Consistency', fontsize=14, fontweight='bold')
axes[1].grid(True, alpha=0.3)

plt.tight_layout()
plt.savefig('driver_a_qualifying_analysis.png', dpi=300)
plt.show()

# Export summary statistics
summary_stats = df[['Min Apex Speed', 'Max Brake Pressure']].describe()
print("\nSummary Statistics:")
print(summary_stats)

df.to_csv('driver_a_qualifying_metrics.csv', index=False)
```

This script automates the extraction of corner-specific metrics across an entire qualifying session, plotting lap time progression and apex speed consistency. Extend the analysis by incorporating additional channels such as steering angle standard deviation, throttle application timing, and GPS-based trajectory deviation from the ideal racing line. ## Exercise 2: Damper Velocity Histogram Tuning & Anti-Roll Bar Optimization

Suspension dampers constitute the primary tool for controlling transient chassis dynamics, regulating the rate at which kinetic energy dissipates during body roll, pitch, and heave motions. Unlike springs which merely store and release energy, dampers convert mechanical motion into heat through viscous fluid shear or magnetorheological resistance, thereby governing how quickly the suspension responds to road surface irregularities and driver control inputs. Optimal damper tuning balances conflicting objectives: sufficient low-speed damping to control body motions and maintain aerodynamic platform stability, while preserving high-speed compliance to permit the tire contact patch to conform to track surface undulations without unloading. This exercise guides you through the rigorous process of analyzing damper velocity histograms extracted from telemetry data, diagnosing handling imbalances attributable to damper mistuning, and systematically optimizing anti-roll bar stiffness distribution to achieve neutral mid-corner balance.

Professional damper tuning relies on empirical force-velocity characterization obtained from dedicated damper dynamometers. These hydraulic test rigs subject the damper to controlled sinusoidal displacement cycles across a range of frequencies and amplitudes, measuring the resulting force output at each velocity point. The force-velocity curve reveals the damper's behavior in bump (extension) and rebound (compression) directions across low-speed (less than fifty millimeters per second), mid-speed (fifty to two hundred millimeters per second), and high-speed (exceeding two hundred millimeters per second) regimes. Modern adjustable dampers provide independent adjustment of low-speed bump, low-speed rebound, high-speed bump, and high-speed rebound via external adjuster knobs that alter valve preload or shim stack stiffness. Each click typically modifies damping force by approximately three to five percent, permitting fine-grained tuning resolution.

Begin this exercise by extracting suspension displacement telemetry from a representative race stint. Open the telemetry log in MoTeC i2 Pro and locate the four suspension potentiometer channels: Front Left Displacement, Front Right Displacement, Rear Left Displacement, and Rear Right Displacement. These channels measure the vertical motion of the wheel assembly relative to the chassis, typically outputting zero millimeters at static ride height and positive values during bump (upward wheel travel relative to body). Verify sensor calibration by inspecting the displacement range during a slow-speed pit lane exit; the suspension should exhibit symmetric oscillation around the static value with no evidence of clipping or dropout indicating sensor malignment or wiring faults.

Compute damper velocities by differentiating the displacement signals with respect to time. In MoTeC i2 Pro, create four new math channels labeled FL Damper Velocity, FR Damper Velocity, RL Damper Velocity, and RR Damper Velocity. The formula for each channel applies a first-order finite difference approximation: `([Channel] - [Channel](shift=-1)) / 0.001`, where the shift operator accesses the prior sample and the denominator represents the telemetry sampling period in seconds, typically one millisecond at one-kilohertz logging rate. Apply a low-pass Butterworth filter with a cutoff frequency of twenty hertz to remove high-frequency noise introduced by numerical differentiation. The resulting velocity traces express damper speed in millimeters per second, with positive values indicating bump (extension) and negative values indicating rebound (compression).

Generate damper velocity histograms to visualize the statistical distribution of suspension motion during the session. MoTeC i2 Pro's histogram function automatically bins velocity data and plots frequency counts. Create a histogram worksheet displaying all four corner damper velocities on a common X-axis scaled from negative five hundred to positive five hundred millimeters per second. Configure bin width to ten millimeters per second, yielding one hundred discrete velocity bins. The histogram shape reveals crucial tuning insights: a symmetric distribution centered near zero indicates balanced suspension kinematics and minimal aero platform pitch oscillation, while asymmetry with excess rebound activity suggests insufficient rebound damping permitting the suspension to extend too rapidly after bump events, destabilizing the tire contact patch.

Analyze the histogram peak concentrations to identify dominant suspension motions. In a well-balanced GT3 car on a smooth circuit, the histogram typically exhibits a tall central peak between negative fifty and positive fifty millimeters per second, representing small-amplitude high-frequency motions as the suspension tracks subtle pavement irregularities. Secondary peaks in the one hundred to two hundred millimeters per second range correspond to transient body motions during corner entry weight transfer and mid-corner roll dynamics. Extreme outliers exceeding four hundred millimeters per second indicate harsh kerb strikes or suspension bottoming events that risk component damage and should be minimized through ride height adjustment or progressive bump stop tuning.

Quantify the damper duty cycle by calculating the cumulative percentage of time spent in each velocity regime. Integrate the histogram bins and express results as percentages: low-speed regime (less than fifty millimeters per second absolute velocity), mid-speed regime (fifty to two hundred millimeters per second), and high-speed regime (exceeding two hundred millimeters per second). A typical optimal distribution allocates seventy percent low-speed, twenty-five percent mid-speed, and five percent high-speed. Excessive high-speed duty indicates the suspension is frequently slamming into bump stops or rebounding violently, signaling the need for softer high-speed damping adjustments or increased bump stop progression rate.

Correlate damper velocity histograms to driver handling feedback. If the driver reports mid-corner understeer, examine the front axle damper histograms. Understeer often correlates with insufficient front rebound damping, permitting the front suspension to extend too quickly after initial corner entry compression, unloading the front tire contact patches and reducing steering authority. Conversely, if the driver describes corner entry rear instability or oversteer, inspect the rear axle histograms for excessive rebound velocity, suggesting the rear suspension extends too aggressively as weight transfers forward during braking, reducing rear tire vertical load and grip.

Implement systematic damper adjustments using a controlled test methodology. Begin by establishing a baseline damper configuration recorded on the suspension setup sheet: document the current clicker positions for low-speed bump, low-speed rebound, high-speed bump, and high-speed rebound at each corner. Execute a baseline telemetry capture session consisting of five consistent laps at race pace. Import this baseline into MoTeC i2 Pro, generate damper velocity histograms, and record the histogram statistics in a spreadsheet.

Modify the front rebound damping by adding four clicks (approximately fifteen to twenty percent force increase) to both front dampers. Execute a second five-lap session maintaining identical driving inputs and track conditions. Import the new telemetry, overlay the updated damper velocity histograms atop the baseline, and quantify the changes. Increased rebound damping should shift the front histogram distribution toward lower peak velocities in the rebound direction, indicating the damper is resisting extension more effectively. Simultaneously review the lap time delta and driver subjective feedback regarding front-end stability and steering response. If lap time improves and the driver reports better turn-in precision, the adjustment moves in the correct direction.

Construct a damper sensitivity matrix by systematically varying each damper adjustment parameter across its full range and recording the resulting lap time and handling balance outcomes. This matrix, organized in spreadsheet format, provides a comprehensive map of the suspension tuning landscape. Each row represents a unique damper configuration, and columns record the clicker positions, lap time, minimum apex speed for a reference corner, driver subjective rating, and key histogram statistics. Transition to anti-roll bar optimization, addressing lateral load transfer distribution between front and rear axles during cornering. Anti-roll bars, also termed sway bars or stabilizer bars, resist body roll by mechanically coupling the left and right suspension assemblies via a torsional spring element. Increasing anti-roll bar stiffness at one axle increases that axle's share of total lateral load transfer, reducing grip at that end and inducing understeer (front bar stiffening) or oversteer (rear bar stiffening). Professional race cars feature adjustable blade-style or tube-style anti-roll bars with discrete mounting positions that alter effective lever arm length, permitting stiffness tuning in increments typically corresponding to five to ten percent rate changes.

Measure the current anti-roll bar configuration by physically inspecting the suspension assembly. The anti-roll bar connects to the suspension uprights via adjustable drop links, and stiffness adjusts by repositioning these links within a series of mounting holes machined into the bar arms or chassis brackets. Count the hole position from the inboard reference and record this on the setup sheet. Most GT3 cars provide five to seven adjustment positions per axle. A stiffer setting (longer lever arm) positions the drop link farther from the bar's torsional axis.

Diagnose mid-corner balance using telemetry-derived roll gradient analysis. Create a math channel computing chassis roll angle from the lateral accelerometer and suspension displacement differentials. The roll angle estimates via: `Roll Angle ≈ arctan((FL Displacement - FR Displacement) / Track Width)`, where track width is the lateral distance between left and right wheel centerlines, typically 1600 millimeters for GT3 machinery. Plot roll angle versus lateral acceleration to generate a roll gradient curve. The slope of this curve, expressed in degrees per G, indicates chassis roll stiffness. Compare front and rear roll gradients: if the front gradient exceeds the rear, the front axle resists roll more aggressively, transferring a disproportionate share of lateral load and promoting understeer.

Implement anti-roll bar adjustments to achieve target balance. If the car exhibits persistent mid-corner understeer despite neutral driver inputs, reduce front anti-roll bar stiffness by moving the drop link inboard one position. This decreases front load transfer share, allowing the front tires to maintain more equal vertical loads across left and right contact patches, enhancing front grip. Simultaneously, consider increasing rear anti-roll bar stiffness by one position to shift load transfer rearward, intentionally provoking mild oversteer to counteract the understeer tendency. Execute a test session, capture telemetry, and regenerate the roll gradient analysis to confirm the load transfer distribution shifted as intended.

Validate anti-roll bar tuning through direct tire temperature measurement. After a five-lap run at race pace, immediately drive into the pit lane and deploy infrared tire temperature pyrometers to measure surface temperatures across the tread width at three positions: inner edge, center, and outer edge. Record temperatures for all four tires in a tabular format. Optimal anti-roll bar tuning produces symmetric temperature gradients across the tread width with peak temperature at the center or slightly biased toward the outer edge, indicating even contact patch loading. If the outside edge temperature exceeds the inside edge by more than fifteen Celsius, excessive camber or anti-roll bar stiffness is overloading the outer tire during cornering, suggesting a reduction in anti-roll bar stiffness at that axle.

Construct a comprehensive setup sensitivity matrix integrating damper adjustments, anti-roll bar positions, and tire pressure variations. This matrix, spanning multiple test sessions across diverse track conditions, quantifies the interdependencies between suspension parameters. For example, increasing front anti-roll bar stiffness may necessitate a compensating reduction in front rebound damping to maintain front-end stability during transient weight transfer. The matrix format organizes setup parameters in rows and performance metrics (lap time, apex speed, driver rating) in columns, with conditional formatting highlighting the optimal configuration based on weighted scoring.

Automate anti-roll bar sensitivity analysis using MATLAB's Vehicle Dynamics Blockset. Construct a quarter-car suspension model parameterized with measured spring rates, damper force-velocity curves, anti-roll bar torsional stiffness, and kinematic hardpoint coordinates. Simulate a standardized cornering maneuver such as a constant-radius circle at one lateral G, varying anti-roll bar stiffness across its adjustment range. Extract simulated tire vertical loads and compute the lateral load transfer distribution percentage. Plot this distribution against anti-roll bar stiffness to visualize the tuning sensitivity. The MATLAB script below demonstrates this workflow:

```matlab
%% Anti-Roll Bar Sensitivity Simulation
% Quarter-car suspension model with parametric anti-roll bar tuning

%% Vehicle Parameters
m_sprung = 350;  % Sprung mass per corner [kg]
m_unsprung = 40;  % Unsprung mass [kg]
k_spring = 70000;  % Spring rate [N/m]
k_tire = 200000;  % Tire vertical stiffness [N/m]
c_damper = 3500;  % Damper coefficient [Ns/m]
track_width = 1.6;  % Track width [m]
roll_center_height = 0.05;  % Roll center height [m]
cg_height = 0.45;  % Center of gravity height [m]

%% Anti-Roll Bar Stiffness Range
arb_stiffness_range = linspace(10000, 80000, 15);  % [Nm/rad]
num_configs = length(arb_stiffness_range);

%% Lateral Acceleration Input
lat_accel = 1.0;  % [g]
g = 9.81;  % [m/s^2]

%% Preallocate Results
load_transfer = zeros(num_configs, 1);
outside_tire_load = zeros(num_configs, 1);
inside_tire_load = zeros(num_configs, 1);

%% Simulate Each Configuration
for idx = 1:num_configs
    k_arb = arb_stiffness_range(idx);
    
    % Compute roll angle (simplified quasi-static model)
    M_roll = m_sprung * lat_accel * g * (cg_height - roll_center_height);
    k_roll_total = k_spring * (track_width/2)^2 + k_arb;
    roll_angle = M_roll / k_roll_total;  % [rad]
    
    % Compute lateral load transfer
    delta_Fz = M_roll / track_width;  % [N]
    
    % Static vertical load per tire
    Fz_static = (m_sprung + m_unsprung) * g / 2;
    
    % Dynamic vertical loads
    Fz_outside = Fz_static + delta_Fz;
    Fz_inside = Fz_static - delta_Fz;
    
    % Store results
    load_transfer(idx) = delta_Fz;
    outside_tire_load(idx) = Fz_outside;
    inside_tire_load(idx) = Fz_inside;
end

%% Compute Load Transfer Percentage
load_transfer_pct = 100 * load_transfer ./ (outside_tire_load + inside_tire_load);

%% Plot Results
figure('Position', [100, 100, 1200, 500]);

subplot(1, 2, 1);
```

## Exercise 3: Tire Temperature Analysis & Wear Modeling

Tire performance defines the ultimate limit of vehicle dynamics. The pneumatic tire operates as a complex nonlinear system governed by viscoelastic material properties, contact patch pressure distribution, tread compound temperature-dependent friction coefficients, and transient thermal dynamics spanning multiple time scales. Optimal tire management in motorsport requires maintaining compound temperatures within the narrow operating window—typically eighty-five to one hundred five Celsius for slick racing tires—while simultaneously managing tread wear rates to ensure consistent performance across stint duration. This exercise establishes a rigorous tire analysis workflow integrating infrared pyrometry, telemetry-derived slip ratio estimation, and empirical wear modeling to predict degradation trajectories and optimize pit stop timing.

Racing tire compounds exhibit pronounced temperature sensitivity. At temperatures below the optimal window, the rubber compound remains too stiff, reducing contact patch compliance and limiting mechanical grip. As temperature increases into the working range, the compound softens, maximizing the contact area and friction coefficient. Exceeding the optimal range causes the compound to overheat and grain or blister, degrading surface texture and precipitously reducing grip. The tire's thermal mass, approximately twenty to thirty kilograms for a GT3 slick, introduces significant thermal inertia: it requires multiple high-load corners to heat the tire into the working range from cold ambient temperature, and conversely, temperatures decay slowly during caution periods or lower-intensity driving.

Begin this exercise by establishing a tire temperature measurement protocol using professional infrared pyrometers. Acquire a calibrated handheld IR pyrometer with sub-one-degree Celsius accuracy and a measurement range spanning zero to two hundred fifty Celsius. Popular models include the Longacre Professional Series or the RACEceiver Tire Temp Gun. Configure the emissivity setting to 0.95 to account for the non-ideal blackbody radiation characteristics of rubber compounds. Ensure the pyrometer's distance-to-spot ratio (typically twelve-to-one) permits accurate surface temperature capture when positioned fifty to sixty millimeters from the tire tread.

Execute a baseline tire temperature capture session. After completing a five-lap race simulation run, immediately drive into the pit lane without excessive cooling-down laps that would allow tire temperatures to decay. Analyze the tire temperature distribution to diagnose suspension geometry and load transfer issues. Optimal alignment and anti-roll bar tuning produces symmetric temperature gradients with peak temperature at the tread center or slightly biased toward the outer edge under cornering load. Compute the temperature spread across the tread width by subtracting the inner edge temperature from the outer edge temperature. If the front left tire exhibits an outer edge temperature of one hundred two Celsius while the inner edge reads eighty-eight Celsius, this fourteen-degree spread indicates excessive positive camber or insufficient anti-roll bar stiffness, causing the tire to roll onto the outer edge excessively during left-hand cornering. Adjust static camber more negative (inward wheel tilt) by one-half degree and retest.

Correlate tire temperatures to telemetry-derived slip ratios. Tire slip ratio, defined as the percentage difference between tire rotational velocity and vehicle ground speed, directly influences heat generation within the contact patch. Excessive slip under braking or acceleration shears the tread compound, converting kinetic energy into heat and accelerating wear. Create a math channel in MoTeC i2 Pro computing longitudinal slip ratio: `Slip Ratio = ((Wheel Speed - Vehicle Speed) / Vehicle Speed) * 100`, where wheel speed derives from the individual corner wheel speed sensors and vehicle speed from GPS. Ideal threshold braking maintains slip ratios between eight and fifteen percent, maximizing deceleration force while avoiding full lock-up that would generate extreme localized heating and flat-spotting.

Construct a tire temperature evolution model predicting tread surface temperature as a function of cumulative energy dissipation. The model integrates heat generation from slip-induced friction and heat rejection via convection and radiation. Begin with a first-order lumped-capacitance thermal model:

$$\frac{dT}{dt} = \frac{Q_{gen} - Q_{loss}}{m \cdot c_p}$$

where $T$ is tire temperature, $Q_{gen}$ is heat generation rate from slip energy, $Q_{loss}$ is convective and radiative heat loss, $m$ is tire thermal mass, and $c_p$ is specific heat capacity of the rubber compound. Heat generation rate estimates as:

$$Q_{gen} = F_x \cdot V_{slip}$$

where $F_x$ is longitudinal tire force and $V_{slip}$ is slip velocity magnitude. Implement this model in Python by integrating telemetry data streams:

```python
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt

# Load telemetry data (assuming CSV export from MoTeC i2 Pro)
data = pd.read_csv('race_stint_telemetry.csv')

# Extract required channels
time = data['Time'].values  # [s]
wheel_speed_FL = data['Wheel Speed FL'].values  # [km/h]
vehicle_speed = data['GPS Speed'].values  # [km/h]
brake_pressure = data['Brake Pressure'].values  # [bar]
long_accel = data['Longitudinal Accel'].values  # [g]

# Convert units
wheel_speed_FL_ms = wheel_speed_FL / 3.6  # [m/s]
vehicle_speed_ms = vehicle_speed / 3.6  # [m/s]

# Compute slip velocity
slip_velocity = wheel_speed_FL_ms - vehicle_speed_ms  # [m/s]

# Estimate longitudinal tire force (simplified)
vehicle_mass = 1300  # [kg]
Fx = vehicle_mass * long_accel * 9.81 / 4  # [N] - force per tire

# Tire thermal parameters
m_tire = 25.0  # Tire thermal mass [kg]
cp_tire = 1200.0  # Specific heat capacity [J/(kg·K)]
h_conv = 40.0  # Convective heat transfer coefficient [W/(m^2·K)]
A_surf = 0.35  # Tire surface area [m^2]
T_ambient = 25.0  # Ambient temperature [°C]

# Initialize temperature array
T_tire = np.zeros(len(time))
T_tire[0] = T_ambient

# Time step
dt = np.mean(np.diff(time))

# Integrate thermal model
for i in range(1, len(time)):
    # Heat generation
    Q_gen = Fx[i] * abs(slip_velocity[i])  # [W]
    
    # Heat loss (convection only, simplified)
    Q_loss = h_conv * A_surf * (T_tire[i-1] - T_ambient)  # [W]
    
    # Temperature rate of change
    dT_dt = (Q_gen - Q_loss) / (m_tire * cp_tire)
    
    # Euler integration
    T_tire[i] = T_tire[i-1] + dT_dt * dt

# Plot results
fig, axes = plt.subplots(3, 1, figsize=(14, 10), sharex=True)

axes[0].plot(time, vehicle_speed, color='blue', linewidth=1.5, label='Vehicle Speed')
axes[0].set_ylabel('Speed [km/h]', fontsize=12, fontweight='bold')
axes[0].legend(loc='upper right', fontsize=10)
axes[0].grid(True, alpha=0.3)

axes[1].plot(time, slip_velocity, color='red', linewidth=1.5, label='Slip Velocity')
axes[1].set_ylabel('Slip Velocity [m/s]', fontsize=12, fontweight='bold')
axes[1].legend(loc='upper right', fontsize=10)
axes[1].grid(True, alpha=0.3)

axes[2].plot(time, T_tire, color='green', linewidth=2.0, label='Predicted Tire Temp')
axes[2].axhline(y=95, color='orange', linestyle='--', linewidth=1.5, label='Optimal Temp Range')
axes[2].axhline(y=85, color='orange', linestyle='--', linewidth=1.5)
axes[2].set_xlabel('Time [s]', fontsize=12, fontweight='bold')
axes[2].set_ylabel('Tire Temp [°C]', fontsize=12, fontweight='bold')
axes[2].legend(loc='upper left', fontsize=10)
axes[2].grid(True, alpha=0.3)

plt.tight_layout()
plt.savefig('tire_thermal_model_output.png', dpi=300)
plt.show()

# Export predicted temperatures
output_df = pd.DataFrame({
    'Time': time,
    'Predicted Tire Temperature': T_tire
})
output_df.to_csv('tire_temperature_predictions.csv', index=False)

print("Tire thermal model simulation complete.")
print(f"Peak tire temperature: {np.max(T_tire):.1f} °C")
print(f"Mean tire temperature: {np.mean(T_tire):.1f} °C")
```
