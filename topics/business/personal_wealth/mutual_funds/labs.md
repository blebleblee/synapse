# Operational Verification Labs: Mutual Funds

## Objective & Operational Lab Setup

These operational verification labs deliver hands-on mastery of mutual fund analysis, portfolio construction, and performance attribution for personal wealth management practitioners. You will construct complete financial models that reverse-engineer fund prospectuses into actionable investment decisions, build multi-period return attribution frameworks that isolate manager skill from market beta, and stress-test portfolio allocations against historical crisis scenarios using actual fund data. The laboratory environment requires spreadsheet software capable of handling array formulas and statistical functions (Microsoft Excel 2016+ or Google Sheets), access to mutual fund prospectuses and historical NAV data (available from fund company websites or financial data providers like Morningstar), and a PDF reader for regulatory filings. Each exercise builds operational competency through complete, zero-placeholder implementations that mirror the analytical workflows used by registered investment advisors, family office analysts, and certified financial planners managing client portfolios.

The pedagogical architecture prioritizes execution over theory. You will spend eighty percent of lab time building working models with actual fund tickers, real expense ratios, and historical return series, then twenty percent interpreting results through the lens of modern portfolio theory and investment policy statements. This inversion ensures that abstract concepts like tracking error, information ratio, and style drift emerge organically from empirical observation rather than remaining disconnected mathematical artifacts. The laboratory setup assumes you possess intermediate spreadsheet proficiency including named ranges, conditional formatting, and pivot tables, alongside foundational knowledge of net asset value calculation, expense ratio mechanics, and the distinction between load and no-load share classes. If you lack access to premium financial databases, all exercises can be completed using freely available data from fund company websites, the SEC's EDGAR database for N-1A registration statements, and Yahoo Finance for historical adjusted closing prices of benchmark indices.

Establish your analytical workspace by creating a dedicated project directory containing three subdirectories: `prospectus_library` for downloaded fund documents, `data_feeds` for CSV exports of historical NAV and benchmark data, and `working_models` for your spreadsheet files. Download prospectuses for at least one fund from each major category: a large-cap equity index fund (such as Vanguard 500 Index Fund VFIAX), an actively managed growth fund (such as Fidelity Contrafund FCNTX), a total bond market fund (such as Vanguard Total Bond Market Index Fund VBTLX), and a balanced allocation fund (such as Vanguard Balanced Index Fund VBIAX). Extract the following data points from each prospectus: gross expense ratio, net expense ratio after fee waivers, 12b-1 distribution fees if applicable, front-end or deferred sales loads, minimum initial investment, benchmark index, investment objective statement, and top ten holdings with sector weights. For historical NAV data, export daily adjusted NAV from fund inception or the past fifteen years, whichever is shorter, alongside corresponding daily returns for the stated benchmark index. This preparatory data extraction transforms regulatory documents into structured datasets ready for quantitative analysis, replicating the operational workflow that precedes every investment committee recommendation.

The laboratory methodology follows a build-verify-stress progression. Each exercise begins with a complete implementation specification including exact cell references, formula syntax, and conditional logic, followed by verification procedures using known test cases with documented expected outcomes, then concludes with stress testing protocols that push models to edge cases and historical crisis periods. This three-phase structure develops the operational discipline required for fiduciary responsibility, where portfolio recommendations must withstand not only favorable market conditions but also the extreme drawdowns, liquidity freezes, and correlation breakdowns that characterize systemic crises. You will emerge from these labs capable of independently evaluating fund prospectuses, constructing risk-adjusted performance metrics, decomposing returns into allocation and selection effects, and articulating investment recommendations with quantitative rigor suitable for inclusion in client investment policy statements.

Cell I33 equals `=I6/I32`. Cell I34 equals `=I7/I32`, and so forth down the first column. Cell J33 equals `=SQRT(J6-I33^2)`. Cell J34 equals `=(J7-I34*I33)/J33`. Continue this pattern to fill the lower triangle of the Cholesky matrix. If your spreadsheet application supports matrix functions, you can alternatively use `=MMULT(TRANSPOSE(H32:N38),H32:N38)` and verify it reproduces the original correlation matrix within rounding error.

Create the simulation data table in columns Q through AD. Column Q starting at row 3 contains "Simulation Run" numbered 1 through 5000. Columns R through X contain "LC Return", "MC Return", "SC Return", "Intl Return", "IG Return", "HY Return", "REIT Return" representing simulated annual returns for each asset class. Column Y contains "Portfolio Return (%)". Column Z contains "Portfolio Value ($)".

In cell R3, generate a random normal variable with `=NORM.INV(RAND(),0,1)` and copy across through X3 to create seven independent standard normal draws. These uncorrelated random variables are then transformed into correlated returns. In cell AA3 (a helper column), calculate the correlated Large-Cap return as `=(I32*R3)*E3 + AVERAGE(all Large-Cap historical returns)`, where E3 references the volatility for large-cap equity and the average return comes from historical data or an assumed risk premium. This formula multiplies the first Cholesky factor by the random normal draw, scales by the asset class volatility, and adds the expected return. Repeat this transformation for each asset class using the appropriate Cholesky factor row and the random normal draws, placing results in columns AB through AH.

This may require several minutes of calculation time depending on processor speed; consider setting calculation mode to manual during setup and triggering a single recalculation when the model is complete.

Calculate value-at-risk metrics from the simulation results. In cell H42 create "Value-at-Risk (VaR) Analysis". Cell H43 "95% VaR ($)", I43 `=PERCENTILE(Z3:Z5002,0.05)-SUM(C3:C32)`, measuring the loss threshold exceeded in only five percent of scenarios. Cell H44 "95% VaR (%)", I44 `=I43/SUM(C3:C32)*100`. Cell H45 "99% VaR ($)", I45 `=PERCENTILE(Z3:Z5002,0.01)-SUM(C3:C32)`. Cell H46 "99% VaR (%)", I46 `=I45/SUM(C3:C32)*100`. Cell H47 "Conditional VaR (CVaR) 95% ($)", I47 `=AVERAGE(IF(Z3:Z5002<=PERCENTILE(Z3:Z5002,0.05),Z3:Z5002))-SUM(C3:C32)`, entered as an array formula with Ctrl+Shift+Enter, calculating the average loss in the worst five percent of scenarios. Cell H48 "CVaR 95% (%)", I48 `=I47/SUM(C3:C32)*100`.

These risk metrics quantify tail exposure: a 95% VaR of -22% means there is a five percent probability of losing at least 22% in a given year, while CVaR of -28% represents the average loss when outcomes fall into that worst five percent. For personal wealth portfolios, these figures inform appropriate position sizing: a retiree with a 4% spending rate and ten-year time horizon can tolerate a 95% VaR of approximately -15% before sequencing risk threatens portfolio sustainability, while a younger accumulator might accept -30% VaR in exchange for higher expected returns.

Implement the liquidity mismatch stress test starting in cell H51 with label "Redemption Stress Test: Forced Liquidation Analysis". ### Diagnostic Decision Tree for Model Failures

When mutual fund analysis models produce unexpected results, execute this diagnostic sequence to isolate root causes. If final wealth calculations differ from manual verification by more than $10, first check that all percentage inputs are divided by 100 in formulas (expense ratios entered as 1.35 must become 0.0135 in calculations). Next, verify that compound return formulas use `(1 + return)` multiplicative form rather than additive `1 + sum(returns)` form, a common source of compounding errors. Inspect beginning balance references in multi-period projections to ensure each period's starting value equals the prior period's ending value without circular references.

If attribution analysis shows allocation and selection effects that sum to values differing from actual excess returns by more than 20 basis points, verify that sector weight columns use decimal form (0.24 for 24%) and that sector return calculations properly subtract benchmark returns for selection effect isolation. Check that SUMPRODUCT formulas multiply corresponding array elements rather than summing entire arrays before multiplication, a frequent error when converting from manual calculations. Confirm that interaction effects are calculated as the product of weight differentials and return differentials, capturing the compounding impact of simultaneous allocation and selection bets.

If rolling regression factor loadings exhibit implausible volatility (coefficient of variation exceeding 0.50) or R-squared values below 0.40, first verify that factor return columns contain actual differential returns (size factor must be small-cap return minus large-cap return, not absolute small-cap returns). Inspect the rolling window array references to ensure each row advances by exactly one quarter without gaps or overlaps: row 47 should reference quarters 1-12, row 48 quarters 2-13, not quarters 1-12 again. Check that LINEST formulas extract coefficients from the correct array positions (market beta is position [1,1], size is [1,2], value is [1,3]) matching the order of factor columns in the regression.

If Monte Carlo simulations produce portfolio return distributions with standard deviations dramatically different from calculated portfolio volatility (deviations exceeding 30%), verify that the Cholesky decomposition matrix when multiplied by its transpose reproduces the original correlation matrix within 0.01 tolerance. Check that each simulated asset class return multiplies the correct Cholesky factor row by the vector of random normal draws, and that volatility scaling occurs after correlation transformation rather than before. Confirm that the portfolio return calculation uses current portfolio weights, not equal weights, and that asset class labels match between the holdings table and the simulation return columns.

If liquidity waterfall calculations show negative amounts liquidated or price impacts exceeding 10%, verify that the MIN and MAX functions correctly implement the liquidation priority: each tier should liquidate the minimum of (amount needed, amount available), with amount needed calculated as MAX(0, total redemption minus cumulative liquidation from higher-liquidity tiers). Check that price impact percentages are applied to liquidated amounts rather than total tier values, and that realized losses accumulate across all tiers rather than replacing previous tier losses.
