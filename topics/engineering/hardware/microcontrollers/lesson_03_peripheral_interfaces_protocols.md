# Lesson 3: Peripheral Interfaces, Communication Protocols

## 1. First-Principles Intuition & Invariants

At the heart of every microcontroller's utility lies its ability to interface with the physical world. A bare silicon die, no matter how sophisticated its instruction pipeline or how large its SRAM banks, remains fundamentally inert without mechanisms to sense external voltages, drive actuators, convert analog signals, and exchange data with neighboring integrated circuits. Peripheral interfaces transform the microcontroller from an isolated computational engine into a node within a distributed electromechanical system, capable of reading temperature sensors, commanding motor drivers, sampling audio waveforms, and orchestrating multi-chip communication fabrics.

The architecture of peripheral subsystems reflects decades of evolutionary pressure toward register-level configurability, hardware-accelerated timing precision, and bus bandwidth conservation. Early microcontrollers exposed peripherals through opaque firmware libraries that obscured the underlying state machines; modern ARM Cortex-M and RISC-V designs present peripherals as memory-mapped register banks, where each bit field directly controls multiplexers, clock dividers, interrupt enables, and DMA request lines. This transparent memory-mapped I/O (MMIO) model empowers the engineer to bypass vendor HAL abstractions, interrogate hardware state through debugger memory watches, and achieve deterministic real-time behavior by programming registers in precisely ordered sequences.

Understanding peripheral interfaces begins with recognizing that every GPIO pin, every timer channel, and every communication bus represents a carefully orchestrated dance between digital logic, analog circuitry, and software state machines. A GPIO pin configured as an output does not simply "turn on"; it engages a CMOS push-pull driver whose P-channel and N-channel MOSFETs are gated by combinatorial logic fed from a GPIO output data register (ODR), with rise and fall times determined by transistor sizing, parasitic capacitance, and configurable slew rate control. A UART transmission does not merely serialize bits; it synthesizes start and stop bits, calculates parity, manages a multi-stage shift register clocked by a baud rate generator derived from a prescaled system clock, and coordinates with DMA engines to stream data from SRAM without CPU intervention.

The invariants governing peripheral design emerge from physical and information-theoretic constraints. Analog-to-digital converters must obey the Nyquist-Shannon sampling theorem, capturing at rates exceeding twice the maximum signal frequency to avoid aliasing. Serial buses must respect setup and hold times, ensuring data stability around clock edges to prevent metastability in receiver flip-flops. DMA controllers must arbitrate bus access through priority matrices or round-robin scheduling to prevent starvation while maintaining cache coherency. Timer compare-match units must latch compare values atomically to avoid race conditions when reconfiguring PWM duty cycles mid-period. These constraints are not negotiable; they represent the boundary between correct operation and undefined behavior, between a motor that spins smoothly and one that stutters, between a sensor reading that converges and one that oscillates.

Peripheral configuration is inherently stateful and sequential. A GPIO pin cannot transition directly from high-impedance input to alternate-function mode; the engineer must first disable the output driver, configure the alternate function multiplexer to select the desired peripheral signal, then enable the peripheral's output control. A timer cannot generate a clean PWM waveform until its prescaler, auto-reload register, and compare registers have been initialized in the correct order, with the timer counter reset to ensure phase alignment. An I2C bus cannot begin a multi-byte transaction without first asserting a START condition, transmitting a 7-bit slave address with read/write bit, and waiting for an ACK pulse driven by the slave's open-drain acknowledgment circuitry. Each of these sequences reflects the internal state machine of the peripheral hardware, and deviating from the prescribed initialization order produces glitches, protocol violations, or silent data corruption.

The register-level interface exposes bit fields that directly control analog biasing circuits, clock routing matrices, and interrupt vector enables. A GPIO port's MODER register selects whether each pin operates as input, output, alternate function, or analog mode, with two bits per pin encoding four mutually exclusive states. A timer's CCMR register configures each capture-compare channel as input capture, output compare, or PWM mode, with prescaler and filter settings that shape the captured waveform's timing precision. An ADC's SMPR register programs per-channel sampling times, trading conversion speed for noise immunity by adjusting the duration that the sample-and-hold capacitor remains connected to the external analog input. These fields are not abstractions; they map one-to-one onto multiplexer control lines, clock enable gates, and comparator reference voltages etched into the silicon.

Peripheral timing behavior is governed by clock domains, prescaler chains, and asynchronous boundary crossers. A timer clocked at 72 MHz with a 16-bit prescaler and 16-bit auto-reload register can generate periods ranging from 13.9 nanoseconds to 59.65 seconds, spanning eleven orders of magnitude through pure integer division. A UART baud rate generator divides the peripheral clock by a mantissa-fractional pair stored in the BRR register, achieving fractional baud rates like 115200.3 baud through dithering techniques that alternate between integer divisors. An I2C peripheral uses a TIMINGR register encoding PRESC, SCLDEL, SDADEL, SCLH, and SCLL fields to synthesize precise setup times, hold times, and clock duty cycles that satisfy the I2C specification's nanosecond-level requirements across varying capacitive loads. These timing parameters are not suggestions; they define the electrical compliance of the physical signal, and misconfiguration produces bus collisions, framing errors, or intermittent glitches that elude software debugging.

Interrupt-driven and DMA-driven I/O represent two paradigms for efficient peripheral servicing. Interrupt-driven I/O trades CPU cycles for low latency, invoking handler routines within microseconds of peripheral events at the cost of context-switch overhead and interrupt-latency jitter. DMA-driven I/O offloads bulk transfers to a dedicated state machine that walks memory descriptors, increments pointers, decrements counters, and asserts bus requests without CPU involvement, achieving sustained throughput limited only by bus arbitration and memory access latency. The choice between paradigms depends on data volume, real-time constraints, and power budgets. A single-byte UART reception warrants an interrupt; a 1024-sample ADC acquisition demands DMA. A GPIO edge triggering a control-loop update fits the interrupt model; a 16-channel audio stream filling ping-pong buffers requires DMA with circular addressing and half-transfer callbacks.

The mental model for peripheral programming is that of a cooperative multitasking system where hardware state machines execute concurrently, driven by independent clock domains, and synchronized through hardware interlocks or software polling. A timer channel capturing an encoder signal operates autonomously, incrementing its counter on every quadrature edge, while the CPU periodically reads the accumulated count through a memory-mapped register. An SPI peripheral shifts out transmit data while simultaneously shifting in receive data, clocked by a self-generated SCK waveform, with both directions progressing in lockstep until the shift register empties. An ADC scans a sequence of channels in round-robin fashion, each conversion triggering a DMA request that writes the result to a memory array, with the entire acquisition coordinated by a hardware trigger from a timer compare event. These concurrent processes interact through shared resources—GPIO pins multiplexed between peripherals, DMA channels contending for bus bandwidth, interrupt priorities determining preemption order—and the engineer's task is to configure the resource allocation to meet real-time deadlines without conflict.

## 2. Core Architecture & Mechanics

### GPIO Configuration and Electrical Characteristics

A general-purpose input/output (GPIO) port aggregates typically 16 pins into a unified control interface, exposing configuration registers that program each pin's electrical behavior, logic function, and peripheral multiplexing. The foundational register is the mode register (MODER), a 32-bit field allocating two bits per pin to select one of four operational modes: input, output, alternate function, or analog. Input mode tri-states the output driver and connects the pin's voltage to a Schmitt-triggered input buffer, whose hysteresis band rejects noise and produces clean logic transitions for signals crossing the threshold. Output mode enables a CMOS push-pull or open-drain driver, sourcing or sinking current according to the bit written to the output data register (ODR). Alternate function mode surrenders the pin to a peripheral like a UART TX line or an SPI MISO signal, routing the peripheral's output through the same physical pad. Analog mode disconnects all digital circuitry to minimize leakage and crosstalk when the pin feeds an ADC input or DAC output, preserving signal integrity by eliminating toggling digital buffers.

The output type register (OTYPER) distinguishes between push-pull and open-drain topologies. A push-pull driver employs complementary P-channel and N-channel MOSFETs in a totem-pole arrangement, actively pulling the pin to VDDIO when high and to ground when low, delivering rail-to-rail voltage swings with low output impedance. An open-drain driver disables the high-side P-channel MOSFET, leaving only the low-side N-channel active, such that the pin can sink current to ground but requires an external pull-up resistor to reach logic high. Open-drain outputs enable wired-AND logic on multi-master buses like I2C, where multiple devices can assert the line low without creating destructive short circuits, and a passive pull-up ensures the line returns high when all drivers release.

The output speed register (OSPEEDR) configures slew rate control by adjusting the gate drive strength of the output MOSFETs. Low-speed settings increase the series resistance in the gate driver, extending rise and fall times to reduce electromagnetic interference (EMI) and crosstalk at the expense of maximum toggle frequency. High-speed settings minimize gate resistance, enabling edge rates below 5 nanoseconds for signals exceeding 50 MHz, but amplifying ringing and ground bounce on shared return paths. The choice of speed setting balances signal integrity against power consumption, as faster edges inject more charge into parasitic capacitances, increasing dynamic current draw. For a 10 MHz SPI clock, a medium-speed setting suffices; for a 100 MHz SDIO interface, very-high-speed becomes mandatory.

The pull-up/pull-down register (PUPDR) activates internal biasing resistors, typically ranging from 30 kΩ to 50 kΩ, that weakly drive the pin toward VDDIO or ground when external circuitry leaves the pin floating. Pull-up resistors prevent undefined logic levels on inputs connected to open-collector or open-drain outputs, ensuring the pin reads high when no external driver asserts low. Pull-down resistors bias unused pins or detect disconnected cables by holding the line low until an external source actively drives high. Internal pull resistors simplify board design by eliminating discrete components, but their tolerance and temperature coefficient make them unsuitable for precision analog biasing or precise current limiting.

The alternate function registers (AFRL and AFRH) map each pin to one of up to 16 peripheral functions through a 4-bit selector field. A pin on GPIOA might alternate between USART2_TX (AF7), TIM2_CH1 (AF1), and SPI1_MOSI (AF5), selected by writing the corresponding function code into the appropriate nibble. The alternate function multiplexer resides between the GPIO logic and the peripheral signal router, implementing a crossbar switch that steers peripheral outputs to the pin driver and pin inputs to peripheral receivers. This flexibility allows a single physical pin to serve multiple roles across different firmware configurations, accommodating diverse board layouts without redesigning the silicon.

Reading and writing GPIO state proceeds through the input data register (IDR), output data register (ODR), and bit set/reset register (BSRR). The IDR is a read-only mirror of the pin voltages after passing through Schmitt triggers, capturing the physical state regardless of whether the pin is configured as input or output. The ODR is a read-write latch controlling the output driver state, but writing to it suffers from read-modify-write hazards in multi-threaded or interrupt-driven code. The BSRR provides atomic bit manipulation, with the lower 16 bits setting corresponding ODR bits high and the upper 16 bits resetting them low, executed as a single bus transaction that eliminates race conditions. To toggle a pin, write a 1 to the reset field in one cycle and the set field in the next; to set multiple pins atomically, combine their bit positions with bitwise OR.

### Timer/Counter Architectures and PWM Generation

Timers form the temporal backbone of embedded control, generating precise delays, measuring external event timing, producing PWM waveforms, and triggering ADC conversions with sub-microsecond determinism. A general-purpose timer consists of a 16-bit or 32-bit free-running counter, a programmable prescaler, an auto-reload register defining the count period, and multiple capture-compare channels offering independent timing functions. The prescaler divides the timer's input clock by a 16-bit value plus one, extending the minimum time resolution from the raw clock period to a coarser granularity suitable for millisecond or second intervals. For a 72 MHz timer clock and a prescaler of 71, the counter increments every microsecond, spanning 65.536 milliseconds before overflowing in a 16-bit timer.

The counter register (CNT) increments or decrements on every prescaled clock edge, wrapping from zero to the auto-reload register (ARR) value in upcounting mode, or from ARR to zero in downcounting mode. Center-aligned mode reverses direction at both boundaries, creating a triangular waveform that centers PWM pulses within each period and doubles the effective resolution for a given ARR value. An update event fires when the counter wraps, reloading shadow registers with buffered values to ensure glitch-free reconfiguration of PWM duty cycles or capture thresholds mid-operation. The update event can trigger an interrupt or a DMA request, enabling periodic servicing of control loops or buffer refreshes without polling overhead.

Each capture-compare channel pairs a compare register (CCRx) with a comparator that monitors the counter value, asserting an output signal when CNT matches CCRx. In output compare mode, this signal directly drives a GPIO pin configured for the timer's alternate function, toggling, pulsing, or PWM-modulating the output according to the channel's output mode bits (OCxM) in the capture-compare mode register (CCMR). PWM mode 1 outputs high when CNT is less than CCRx and low otherwise, producing a pulse whose width is proportional to CCRx divided by ARR. PWM mode 2 inverts this logic, useful for complementary outputs in motor control H-bridges. The output polarity (CCxP) bit in the capture-compare enable register (CCER) inverts the signal again, accommodating active-low drivers or reversed logic conventions.

Generating a 20 kHz PWM waveform with 10-bit resolution on a 72 MHz timer requires setting ARR to 1023 (providing 1024 distinct duty cycles) and the prescaler to 2 (yielding a 24 MHz counter clock). The update frequency becomes 24 MHz divided by 1024, equaling 23.4375 kHz—close to but not exactly 20 kHz due to integer quantization. Achieving precisely 20 kHz demands ARR = 3599 with prescaler 0, but sacrificing resolution to 3600 steps. This tradeoff between frequency accuracy and duty-cycle granularity permeates timer configuration, forcing engineering judgment based on application requirements. Servo motors tolerate ±5% frequency error but demand 0.1% duty cycle precision for positional accuracy; LED dimming accepts 8-bit resolution but requires jitter-free frequency to avoid visible flicker.

Input capture mode repurposes the compare channel to timestamp external events, latching the counter value into CCRx when a configured edge transition occurs on the timer input pin. The capture event triggers an interrupt or DMA request, allowing software to retrieve the timestamp and calculate elapsed intervals between edges. Configuring the input capture filter (ICxF) in the CCMR register averages consecutive samples to reject glitches, trading edge-detection latency for noise immunity. A four-sample filter at the timer's full clock rate provides sub-microsecond noise rejection; an eight-sample filter at a divided clock extends rejection to tens of microseconds, suitable for mechanical switch debouncing. The input prescaler (ICxPSC) decimates capture events, triggering every second, fourth, or eighth edge to reduce interrupt overhead when measuring slow repetitive signals like 1 Hz heartbeat tones.

Timers interact with other peripherals through hardware trigger connections routed via the trigger selection (TS) field in the slave mode control register (SMCR). A timer can slave its counter to another timer's update event, chaining prescalers to achieve arbitrary division ratios exceeding 32 bits. A timer can gate its counting on an external trigger input, enabling precise pulse-width measurement by starting the counter on a rising edge and stopping on a falling edge. A timer can trigger ADC conversions through its update event or a specific compare-match event, synchronizing sampling instants to PWM switching edges for current sensing in motor control applications. These inter-peripheral links bypass the CPU, reducing latency and jitter to the determinism of silicon propagation delays.

### Analog-to-Digital and Digital-to-Analog Converters

Analog-to-digital converters (ADCs) quantize continuous voltage signals into discrete digital codes, enabling microcontrollers to interface with resistive sensors, thermocouples, microphones, and other analog transducers. A successive-approximation-register (SAR) ADC, the most common topology in microcontrollers, employs a binary search algorithm coordinated by a state machine that iteratively compares the input voltage against a DAC-generated reference, refining the result one bit per clock cycle. A 12-bit SAR ADC requires 12 comparison cycles plus acquisition time, yielding conversion rates up to several megasamples per second when clocked at tens of megahertz.

The conversion process begins with an acquisition phase, during which an analog switch connects the input pin to a sample-and-hold capacitor (typically 5 to 20 picofarads) that charges through the pin's source impedance. The sampling time, programmed in the ADC_SMPRx registers as a multiple of ADC clock cycles, must exceed the RC time constant formed by the source impedance and the sampling capacitor to ensure the voltage settles within one least-significant bit (LSB). For a 10 kΩ source impedance and 10 pF capacitor, the time constant is 100 nanoseconds, requiring roughly five time constants (500 nanoseconds) for 1% settling, translating to 7.5 ADC clock cycles at 15 MHz. Insufficient sampling time causes undercharging, biasing results low and introducing nonlinearity as the residual charging error varies with input voltage.

After acquisition, the ADC disconnects the sample capacitor and executes the successive-approximation algorithm. The internal DAC sets its output to mid-scale (2048 out of 4096 for a 12-bit converter), and a comparator determines whether the input voltage exceeds this threshold. If the input is higher, the most-significant bit (MSB) of the result is set to 1, and the DAC moves to the three-quarter-scale point (3072); if lower, the MSB is 0, and the DAC moves to one-quarter scale (1024). This process repeats for each bit, halving the remaining range at every step, until the least-significant bit (LSB) converges. The final digital code represents the input voltage as a fraction of the reference voltage (VREF+), with each LSB corresponding to VREF+ divided by 4096 for a 12-bit ADC.

Reference voltage accuracy and stability directly govern conversion accuracy. The internal reference voltage, derived from a bandgap circuit, typically exhibits 1% initial accuracy and 50 ppm/°C temperature drift, acceptable for non-critical measurements but inadequate for precision sensor applications. External references like the REF3030 provide 0.1% initial accuracy and 10 ppm/°C drift, at the cost of additional board area and supply current. The reference feeds both the SAR ADC's internal DAC and a positive input of the comparator, forming the voltage scale against which all conversions are measured. Noise on the reference voltage directly couples into conversion results as common-mode error; a 10 mV ripple produces 10 mV / (3.3 V / 4096) ≈ 12 LSB of jitter, swamping a 12-bit converter's quantization noise.

Multiple ADC channels share a single SAR core through an analog multiplexer that sequentially connects input pins to the sample-and-hold circuit. The regular sequence registers (ADC_SQRx) define the scan order, channel count, and per-channel sampling times, enabling round-robin acquisition of up to 16 channels in a single scan triggered by software, a timer event, or an external signal. The injected sequence registers (ADC_JSQRx) preempt the regular sequence to service high-priority channels with lower latency, useful for over-current detection that must interrupt bulk data acquisition. Each conversion result writes to a 16-bit data register (ADC_DR for regular channels, ADC_JDRx for injected channels), with a DMA request automatically transferring the value to memory without CPU intervention.

Oversampling and decimation extend effective resolution beyond the ADC's native bit depth by averaging multiple conversions, trading sample rate for reduced noise. Acquiring four samples and averaging them increases resolution by one bit, as uncorrelated quantization noise adds incoherently while the signal adds coherently, improving the signal-to-noise ratio by 6 dB. Sixteen samples yield two additional bits, 64 samples yield three bits, and so on, following the square-root relationship between oversampling ratio and resolution gain. The microcontroller's hardware oversampling unit (on devices like the STM32L4) automates this process, shifting and accumulating samples in dedicated registers, then right-shifting the sum to produce a final result with extended precision stored in the data register.

Digital-to-analog converters (DACs) perform the inverse operation, synthesizing analog voltages from digital codes to drive analog circuits like amplifiers, voltage-controlled oscillators, or motor speed controllers. Resistor-ladder DACs, common in microcontrollers, use a network of precision resistors arranged in a binary-weighted or R-2R topology to divide the reference voltage into fractions corresponding to each digital code. Writing a 12-bit value to the DAC_DHRx register transfers the code to a shift register, which gates a set of analog switches connecting resistor taps to a summing node, producing an output voltage equal to the code divided by 4096 times the reference voltage.

DAC settling time, the interval required for the output to stabilize within one LSB after a code change, limits the maximum output frequency. A typical 12-bit DAC settles in 3 to 10 microseconds, constraining waveform generation to bandwidths below 100 kHz for large-signal swings. Smaller code changes settle faster, as the internal op-amp buffers experience reduced slew-rate limiting, enabling audio-frequency synthesis when consecutive samples differ by only a few LSBs. DMA-driven DAC waveform generation streams samples from a memory buffer to the DAC data register at regular intervals timed by a hardware trigger from a timer, producing smooth periodic or arbitrary waveforms without CPU involvement. Circular DMA mode wraps the buffer pointer to loop the waveform indefinitely, useful for sinusoidal test tones or DTMF signaling.

### UART: Universal Asynchronous Receiver-Transmitter

UART implements point-to-point asynchronous serial communication, framing data bytes with start and stop bits and optionally appending parity bits for error detection. The transmitter idles with the TX line held high by a pull-up resistor, then initiates a frame by pulling the line low for one bit period, signaling the start bit. The receiver detects the falling edge, waits half a bit period to center its sampling window, then samples the line at the nominal baud rate for the next eight (or nine) data bits, transmitted LSB-first. A single stop bit, held high, follows the data, providing a guaranteed idle interval before the next start bit. The receiver samples the stop bit to verify framing integrity, asserting a framing error flag if the line remains low when a stop bit is expected.

Baud rate generation derives from the peripheral clock through a fractional divider stored in the baud rate register (BRR). The divider consists of a 12-bit mantissa and a 4-bit fraction, enabling precise baud rates like 115200 baud despite non-integer divisors. For a 72 MHz peripheral clock and 115200 baud, the ideal divisor is 625, but the fractional divider allows 625.0000, 625.0625, or 625.1250 by toggling the divisor between 625 and 626 on a 16-cycle basis, dithering the timing error across multiple bit periods. Clock tolerance requirements tighten for higher baud rates and longer frames; a 1% clock error accumulates to 10% error over ten bit periods, causing the receiver's sampling window to drift off the bit center and corrupt the stop bit detection.

The UART status register (USART_SR) exposes transmit and receive buffer state through flags indicating transmit data register empty (TXE), transmission complete (TC), receive data register not empty (RXNE), and various error conditions. Polling TXE before writing the next byte to the data register (USART_DR) ensures the transmit shift register has consumed the previous byte, preventing data loss. Polling RXNE before reading the data register guarantees a new byte has arrived, avoiding stale data. Interrupt-driven I/O arms the TXEIE and RXNEIE interrupt enables, invoking handler routines when buffers require servicing, reducing polling overhead at the cost of interrupt latency and context-switch cycles.

DMA elevates UART throughput by streaming data between memory and the data register without CPU involvement. Configuring the USART_CR3 register's DMAT and DMAR bits enables transmit and receive DMA requests, asserted whenever TXE or RXNE flags set. The DMA controller, programmed with source and destination addresses, transfer count, and channel priority, autonomously walks memory buffers and USART_DR, incrementing pointers and decrementing counters on every transaction. Circular mode wraps the buffer pointer to implement ring buffers for continuous streaming, with half-transfer and transfer-complete interrupts signaling when the buffer reaches midpoint or end, allowing software to process completed data while the DMA fills the remaining half.

Multi-processor communication mode leverages the 9-bit data format to transmit address bytes distinguishing individual slaves on a shared bus. The transmitter sets the ninth bit when transmitting an address, and receivers compare the address against their device ID, ignoring subsequent data bytes unless the address matches. This scheme multiplexes a single UART physical layer across multiple logical endpoints, avoiding the bus arbitration complexity of multi-master protocols at the cost of half-duplex operation and centralized master control.

### SPI: Serial Peripheral Interface

SPI orchestrates synchronous full-duplex communication between a master device and one or more slaves, clocking data on dedicated MOSI (master-out-slave-in) and MISO (master-in-slave-out) lines under control of a master-generated SCK clock and slave-select (NSS) chip-select signals. The master drives SCK, toggling it at a frequency derived from the peripheral clock divided by a prescaler (2, 4, 8, 16, 32, 64, 128, or 256), and simultaneously shifts out MOSI while shifting in MISO, exchanging one bit per clock edge. Data bytes transmit MSB-first or LSB-first, configurable via the LSBFIRST bit in the control register (SPI_CR1), matching the endianness expectations of external peripherals like ADCs, DACs, and flash memories.

Clock polarity (CPOL) and clock phase (CPHA) define four SPI modes dictating the idle state of SCK and the sampling edge timing. Mode 0 (CPOL=0, CPHA=0) idles SCK low and samples MISO on the rising edge, shifting MOSI on the falling edge. Mode 1 (CPOL=0, CPHA=1) idles SCK low but samples MISO on the falling edge, shifting MOSI on the rising edge. Mode 2 (CPOL=1, CPHA=0) idles SCK high, sampling on the falling edge and shifting on the rising edge. Mode 3 (CPOL=1, CPHA=1) idles SCK high, sampling on the rising edge and shifting on the falling edge. The master and slave must agree on the SPI mode; mismatched configurations cause data corruption as the master samples while the slave shifts, or vice versa.

The master initiates a transaction by asserting the NSS line low, selecting a specific slave, then writing a byte to the data register (SPI_DR). The SPI hardware loads this byte into an 8-bit shift register and begins toggling SCK, shifting out MOSI and simultaneously shifting in MISO. When the shift completes, the hardware sets the TXE flag, transfers the received byte from the shift register to SPI_DR, and sets the RXNE flag. The master reads the received byte, writes the next transmit byte, and the cycle repeats. Full-duplex operation means every write produces a corresponding read, even if the application discards the received data or transmits dummy bytes to clock in data from a write-only slave.

Multi-slave topologies employ either dedicated NSS lines for each slave or a shared bus with slaves responding to transmitted address bytes. Dedicated NSS lines require one GPIO per slave, consuming pin resources but enabling simultaneous selection of multiple slaves for broadcast commands or daisy-chained shift registers. Shared-bus addressing multiplexes slaves onto a single set of SPI lines, with each slave decoding the first byte of every transaction to determine if it should respond, but complicates bus turnaround when switching between slaves of differing SPI modes or speeds.

DMA-driven SPI transfers bulk data with minimal CPU overhead, configuring the DMA controller to stream memory arrays to SPI_DR for transmission and from SPI_DR to memory for reception. The SPI_CR2 register's TXDMAEN and RXDMAEN bits enable DMA requests, triggered whenever TXE or RXNE asserts. Ping-pong buffering uses two DMA channels alternating between two memory buffers, with transfer-complete interrupts swapping active buffers while the SPI continues streaming, ensuring uninterrupted data flow for applications like audio sample streaming or high-speed data logging.

### I2C: Inter-Integrated Circuit

I2C implements multi-master, multi-slave communication over a two-wire bus consisting of a bidirectional data line (SDA) and a clock line (SCL), both pulled high by resistors and driven low by open-drain outputs. The open-drain topology enables wired-AND logic, where any device can pull the line low, but a pull-up resistor must supply the high level when all devices release the line. This arrangement supports bus arbitration without destructive contention, as the low level always wins, and multiple masters can coexist by monitoring bus state before and during transmission.

An I2C transaction begins with a START condition, defined as a high-to-low transition on SDA while SCL remains high. The START condition alerts all slaves that an address frame follows, consisting of seven bits identifying the target slave and an eighth bit indicating read (1) or write (0) direction. The transmitting master releases SDA after the eighth clock pulse, allowing the addressed slave to pull SDA low during the ninth clock pulse, driving an acknowledge (ACK) bit that confirms its presence and readiness. If no device acknowledges, SDA remains high (a NACK), signaling an addressing error or absent slave, and the master typically aborts with a STOP condition (SDA rising while SCL is high).

Data transfer proceeds in 8-bit bytes, each followed by an ACK/NACK bit driven by the receiver. In write transactions, the master clocks out data bytes and the slave acknowledges each byte; in read transactions, the slave clocks out data bytes and the master acknowledges each byte except the last, sending a NACK to signal completion. The STOP condition released the bus, returning it to the idle state where both SDA and SCL float high. A repeated START (SDA transitioning low while SCL is high, without an intervening STOP) allows the master to retain bus ownership and address a different slave or change transaction direction without releasing the bus, useful for atomic read-modify-write sequences or multi-target burst transfers.

Clock stretching extends the low period of SCL when a slave device requires additional time to process data, prepare the next byte, or complete an internal operation. The slave holds SCL low after the master releases it, and the master waits until SCL rises high before driving the next clock pulse. Clock stretching accommodates slow peripherals like EEPROMs performing write cycles or sensors executing long-duration measurements, but introduces unbounded latency into bus transactions, complicating real-time scheduling. Not all I2C implementations support clock stretching; software bit-banging may fail to detect a stretched clock, while hardware peripherals typically include a timeout mechanism that aborts transactions exceeding a configurable duration.

Bus arbitration resolves collisions when multiple masters simultaneously transmit START conditions and address frames. Each master monitors SDA while transmitting, comparing the driven bit against the observed line state. If a master drives SDA high (by releasing the open-drain output) but observes SDA low (driven by another master), it has lost arbitration and immediately ceases transmission, deferring to the winning master. Arbitration occurs bit-by-bit, with the master transmitting the lowest binary sequence winning the bus. This non-destructive arbitration ensures that the winning master completes its transaction unaffected by the collision, while the losing master retries after detecting a STOP condition.

The I2C timing register (I2C_TIMINGR on STM32 devices) encodes prescaler (PRESC), SCL low time (SCLL), SCL high time (SCLH), SDA setup time (SCLDEL), and SDA hold time (SDADEL) fields that synthesize compliant bus timing across varying clock frequencies and capacitive loads. For standard-mode (100 kHz) I2C with a 48 MHz peripheral clock, PRESC divides the clock to produce a 1 MHz reference, SCLL and SCLH configure the SCL waveform duty cycle, and SCLDEL and SDADEL insert delays ensuring SDA stability around SCL transitions. Fast-mode (400 kHz) and Fast-mode Plus (1 MHz) require shorter timing parameters and lower pull-up resistances to overcome increased capacitive charging times, trading signal integrity for bus speed.

### DMA: Direct Memory Access Controllers

Direct memory access (DMA) controllers offload bulk data transfers from the CPU by autonomously moving bytes between memory, peripherals, and other DMA-capable endpoints. A DMA transaction is programmed by writing source address, destination address, transfer count, and control flags into a set of channel configuration registers (DMA_CCRx, DMA_CNDTRx, DMA_CPARx, DMA_CMARx). The peripheral asserts a DMA request signal (DMAR or DMAT on UART, RXNE or TXE on ADC, etc.) when it requires servicing, and the DMA controller arbitrates bus access, reads from the source address, writes to the destination address, increments pointers as configured, and decrements the transfer count. When the count reaches zero, the DMA asserts a transfer-complete interrupt and disables the channel.

Memory-to-peripheral transfers read from SRAM and write to a fixed peripheral data register address, useful for transmitting UART buffers or streaming DAC waveforms. Peripheral-to-memory transfers read from a peripheral data register and write to incrementing SRAM addresses, capturing ADC sample arrays or UART receive streams. Memory-to-memory transfers copy data between SRAM regions, accelerating block moves and buffer copies without CPU execution. The DMA increments source and destination addresses independently, controlled by the MINC (memory increment) and PINC (peripheral increment) bits in the configuration register, allowing flexible patterns like writing a constant value to an array (disable source increment) or reading a circular buffer (enable wraparound addressing).

Channel priority resolves contention when multiple DMA channels request bus access simultaneously. Four priority levels (low, medium, high, very high) are assigned via the PL field in the configuration register, with higher-priority channels preempting lower-priority channels' bus cycles. Equal-priority channels arbitrate via round-robin scheduling, ensuring fairness and preventing starvation. High-priority DMA channels service time-critical peripherals like ADCs sampling at megahertz rates, while low-priority channels handle bulk transfers like UART logging or flash programming that tolerate latency.

Circular mode automates continuous streaming by reloading the transfer count and wrapping the memory address pointer when the count reaches zero, eliminating the need for software to reprogram the DMA between transactions. Half-transfer and transfer-complete interrupts fire when the count reaches the midpoint and zero, respectively, signaling double-buffering opportunities where one buffer half is processed while the DMA fills the other half. This ping-pong pattern sustains uninterrupted streaming for audio sample playback, sensor data acquisition, or communication packet buffering.

DMA request multiplexing routes peripheral request signals to DMA channels through a programmable crossbar (DMAMUX on recent STM32 devices), decoupling peripheral identity from channel assignment. Older DMA controllers hardwire specific peripherals to fixed channels, constraining resource allocation and sometimes forcing suboptimal priority assignments. DMAMUX allows any peripheral request to trigger any DMA channel, enabling flexible priority tuning and simplifying firmware portability across product variants with differing peripheral counts.

Interrupt handlers coordinate with DMA by checking transfer-complete flags in the DMA interrupt status register (DMA_ISR) and clearing them via the interrupt flag clear register (DMA_IFCR). A typical pattern polls the half-transfer flag to process the first buffer half while the DMA fills the second half, then polls the transfer-complete flag to process the second half while the DMA wraps to refill the first half. Error flags signal conditions like transfer errors (attempting to access restricted memory), FIFO overrun (peripheral request occurring before the previous transfer completed), or bus errors (AHB transaction aborted), alerting software to exceptional conditions requiring recovery logic or system reset.

## 3. High-Performance Optimization & Failure Modes

Optimizing peripheral performance begins with clock tree configuration, ensuring peripherals receive maximum sustainable clock frequencies without violating setup and hold times or exceeding maximum toggle rates. Advanced microcontrollers partition peripherals across multiple clock domains—APB1 running at half the AHB speed, APB2 matching the AHB, and dedicated high-speed clocks for USB or SDIO—trading clock frequency against bus arbitration latency and power consumption. A timer driving a 100 kHz PWM waveform operates effectively on a 10 MHz APB clock with a prescaler of one and ARR of 99, while an SPI peripheral clocking at 18 MHz demands the full 72 MHz APB2 clock with a prescaler of four. Underclocking peripherals conserves power; overclocking risks metastability and protocol violations.

GPIO output slew rate tuning balances edge sharpness against electromagnetic interference. Fast-slew GPIO generates sub-5-nanosecond edges that excite resonances on PCB traces, producing ringing, crosstalk, and radiated emissions that fail EMC compliance. Medium or low slew rates extend edges to 20 or 50 nanoseconds, damping resonances and reducing high-frequency harmonic content, but limiting maximum toggle rates to several megahertz. Critical signals like SPI clocks or high-speed UART transmit lines demand fast slew to preserve timing margins, while non-critical outputs like status LEDs tolerate slow slew for quieter operation. A heuristic is to select the slowest slew rate that meets signal integrity requirements, verified through oscilloscope measurements of rise time, overshoot, and crosstalk coupling to adjacent pins.

ADC performance optimization requires careful attention to source impedance, sampling time, and reference voltage stability. A high-impedance voltage divider (100 kΩ resistors sensing a battery voltage) must be buffered by a unity-gain operational amplifier to present low output impedance to the ADC, preventing incomplete charging of the sample-and-hold capacitor. Insufficient sampling time manifests as voltage-dependent nonlinearity, where low input voltages convert accurately but high voltages read low due to exponential charging dynamics. Incrementing the sampling time from 7.5 cycles to 19.5 cycles or 71.5 cycles increases acquisition time, allowing higher source impedances at the cost of reduced sample rate. For a 10 kΩ source and 10 pF capacitor, a 71.5-cycle sampling time at 15 MHz ADC clock (4.77 microseconds) permits over 47 time constants of settling, achieving 16-bit linearity despite the ADC's 12-bit resolution.

Reference voltage decoupling prevents supply noise from corrupting ADC results. A 0.1 µF ceramic capacitor and 10 µF tantalum capacitor in parallel at the VREF+ pin form a low-impedance reservoir for transient charging currents drawn by the internal DAC during successive-approximation cycles. The ceramic capacitor's low ESR handles high-frequency switching noise, while the tantalum's larger capacitance stabilizes low-frequency drift. Routing VREF+ and VREF- as differential pairs with ground return minimizes loop area, reducing magnetic field coupling from switching regulators and digital clock traces. A series RC filter (10 Ω resistor, 1 µF capacitor) between the voltage reference IC and VREF+ pin attenuates high-frequency noise, trading reference settling time against improved signal-to-noise ratio.

Timer PWM jitter arises from non-deterministic update event timing when reconfiguring duty cycles mid-period. Writing to CCRx modifies the compare threshold immediately if the preload enable (OCxPE) bit is cleared, causing the PWM output to glitch if the counter has already passed the new threshold but not yet reached the old threshold. Enabling the preload bit shadows CCRx writes in a buffer register, transferring the new value to the active compare register only at the next update event, ensuring duty cycle transitions occur synchronously at period boundaries. For motor control applications demanding jitter-free commutation, the preload mechanism is mandatory; for LED dimming tolerant of occasional glitches, immediate updates simplify firmware.

SPI clock phase and polarity mismatches produce insidious data corruption that evades casual testing but fails intermittently under load. If the master configures CPHA=0 (sampling on the first clock edge) while the slave expects CPHA=1 (sampling on the second edge), the master captures the slave's previous bit while the slave shifts out the current bit, producing a one-bit left shift in received data. This error is reproducible for a given transaction but varies across transactions if the bus state differs, complicating diagnosis. Verification demands oscilloscope capture of MOSI, MISO, and SCK during a known test pattern, confirming that data transitions occur on the expected edges and setup times meet the slave's datasheet specifications. Many SPI peripherals document setup times as ambiguous "nanoseconds before the sampling edge," requiring interpretation of whether "before" refers to the preceding inactive-to-active transition or the subsequent active-to-inactive transition.

I2C bus capacitance limits maximum clock frequency and requires pull-up resistor sizing to maintain signal integrity. The I2C specification defines maximum bus capacitance as 400 pF for standard-mode, 400 pF for fast-mode, and 550 pF for fast-mode plus, encompassing PCB trace capacitance, device pin capacitance, and connector stray capacitance. Pull-up resistance determines the rise time when the bus transitions from low to high, governed by the RC time constant formed with bus capacitance. A 4.7 kΩ pull-up and 100 pF capacitance yield a 470 nanosecond time constant, requiring 2.3 microseconds to reach 90% of VDDIO (five time constants), compatible with 100 kHz standard-mode but violating the 300 nanosecond maximum rise time for 400 kHz fast-mode. Fast-mode demands lower pull-up resistance, typically 1 kΩ to 2.2 kΩ, trading increased idle current (1.5 mA at 3.3V with 2.2 kΩ) for faster rise times. Calculating pull-up resistance proceeds by measuring bus capacitance with an LCR meter, multiplying by the target rise time (0.3 µs / C_bus), and selecting the nearest standard resistor value below the result.

Clock stretching timeout configurations prevent indefinite hangs when a misbehaving I2C slave holds SCL low indefinitely due to firmware deadlock or hardware fault. The I2C_TIMEOUTR register programs a timeout duration in peripheral clock cycles, asserting a timeout error flag if SCL remains low beyond the threshold. Timeout values must exceed the longest legitimate clock stretch by a comfortable margin, accounting for EEPROM write cycles (5 milliseconds), sensor measurements (100 milliseconds for some humidity sensors), and bus capacitance-induced rise time. A 10 millisecond timeout accommodates most peripherals while preventing firmware from blocking indefinitely on a failed bus transaction. The timeout error forces the I2C state machine to abort, reset, and reinitialize, requiring software to detect the error flag, clear it, and potentially reset the offending slave via a GPIO-controlled reset line.

DMA channel priority inversions occur when a high-priority firmware interrupt preempts a low-priority DMA channel's bus grant, causing the DMA transaction to stall while the interrupt handler executes. If the interrupt handler itself initiates a higher-priority DMA transfer (e.g., an ADC overrun interrupt triggering an emergency logging DMA), the original low-priority DMA may starve, accumulating latency until its peripheral FIFO overflows or underflows. Avoiding priority inversion requires carefully assigning DMA priorities such that time-critical peripherals (ADC sampling, motor commutation) use very high priority, moderate-throughput peripherals (UART logging) use medium priority, and background bulk transfers (flash programming) use low priority. Interrupt handlers should avoid initiating DMA transfers unless absolutely necessary, preferring to set flags that the main loop services after the interrupt returns.

Circular DMA buffer overruns occur when the interrupt handler servicing half-transfer or transfer-complete events executes too slowly, allowing the DMA to wrap the buffer and overwrite unprocessed data. A typical failure mode involves an ADC sampling at 100 kHz with a 1024-sample circular buffer, triggering half-transfer interrupts every 5.12 milliseconds. If the interrupt handler requires 6 milliseconds to process 512 samples, the DMA overwrites the second buffer half before the handler completes, corrupting the data. Mitigation strategies include reducing handler execution time through algorithmic optimization or offloading processing to the main loop, increasing buffer size to provide more headroom, reducing sample rate if bandwidth permits, or employing triple-buffering with a state machine that rotates between three buffers, ensuring one buffer is always available for the DMA while two buffers queue for processing.

Register read-modify-write hazards plague GPIO and peripheral configurations in interrupt-driven or multi-threaded firmware. Reading the ODR register, modifying a bit, and writing back the result executes as three distinct bus transactions, during which an interrupt may preempt and modify the same register, causing the subsequent write to clobber the interrupt's change. The BSRR and BRR registers provide atomic set and reset operations, but many peripheral control registers lack equivalent atomic-modify mechanisms. Critical sections protected by interrupt disable (CPSID i / CPSIE i on ARM Cortex-M) or mutex locks serialize register modifications, but introduce latency and complexity. Hardware locking registers (available on some peripherals) enforce exclusive access through a read-check-modify sequence that aborts if another master accessed the register meanwhile, providing atomic semantics at the cost of retry logic and potential starvation.

Peripheral clock gating in low-power modes disables peripheral clocks to conserve energy, but inadvertently freezes timers, halts DMA transfers, and silences UART receivers unless explicitly configured to remain active. The RCC_APBxENR registers control peripheral clock enables, and the RCC_APBxLPENR registers control low-power mode clock enables, forming a two-level hierarchy. Entering sleep mode with UART clock gating enabled causes the receiver to miss incoming bytes, manifesting as sporadic communication failures that correlate with CPU sleep duty cycle. Peripherals requiring continuous operation—UART receivers awaiting wake-up commands, timers maintaining real-time clocks, ADCs sampling asynchronously—must have their low-power clock enable bits set, sacrificing power savings for functional correctness. Quantifying power consumption via current measurements across sleep and active states guides the tradeoff, revealing whether leaving a peripheral clocked consumes acceptable microamperes or unacceptable milliamperes.

Signal integrity failures on high-speed SPI buses arise from inadequate PCB layout, exhibiting inter-symbol interference, clock jitter, and data-dependent skew. A 20 MHz SPI clock with 25 nanosecond bit periods demands controlled impedance routing, minimizing trace length mismatches between SCK, MOSI, and MISO to prevent skew from violating setup and hold times. A 1-inch length mismatch introduces approximately 150 picoseconds of skew (assuming 6-inch per nanosecond propagation velocity), consuming 0.6% of the bit period—acceptable for 20 MHz but marginal for 50 MHz. Ground plane continuity underneath SPI traces maintains stable return current paths, avoiding loop inductance that couples switching noise into adjacent signals. Series termination resistors (22 to 33 ohms) at the driver pins damp reflections on long traces, trading edge sharpness for reduced ringing. Oscilloscope probes clipped directly to device pins capture the actual waveform shapes, revealing overshoot, undershoot, and ringing that PCB layout modifications must eliminate through iterative prototyping.
