# Lesson 1: Floating-Point Arithmetic, Machine Precision, Error Propagation

## 1. First-Principles Intuition & Invariants

Every numerical computation is, at its core, an act of approximation. When a mathematician writes $\sqrt{2}$, they invoke an exact object in $\mathbb{R}$: an infinite, non-repeating decimal whose identity is fixed by the axioms of the real number system. When a computer computes $\sqrt{2}$, it produces a rational number with a fixed number of binary digits, necessarily distinct from the true value. This gap between the mathematical ideal and the representable finite approximation is not an engineering defect to be patched away; it is a structural invariant of any discrete computational system operating over a continuum. The discipline of numerical analysis begins precisely with taking this gap seriously, measuring it rigorously, and designing algorithms that prevent it from growing into catastrophe.

The historical impetus for standardization came from a painful era of incompatibility. Through the 1960s and 1970s, different machines implemented floating-point arithmetic differently: different precisions, different rounding rules, different handling of overflow and division by zero. A program producing correct results on one architecture would silently diverge on another. The IEEE 754 standard, ratified in 1985 and revised in 2008, resolved this chaos by specifying not merely the storage format but the exact result of every arithmetic operation, every rounding decision, and every exceptional case. The standard's most consequential guarantee is that a conforming implementation of addition, subtraction, multiplication, and division must return the floating-point number nearest to the true real-number result, with ties broken by a specified rule. This property, called *correct rounding*, transforms floating-point arithmetic from an ad hoc approximation scheme into a mathematically principled system whose behavior can be formally reasoned about.

To understand what IEEE 754 actually represents, one must internalize the structure of the floating-point number system $\mathbb{F}(\beta, t, e_{\min}, e_{\max})$, parameterized by a base $\beta$, a precision $t$ (the number of significant digits in base $\beta$), and an exponent range $[e_{\min}, e_{\max}]$. Every nonzero, finite element of this system has the form

$$x = \pm m \cdot \beta^e$$

where the *significand* $m$ satisfies $1 \leq m < \beta$ when normalized, and $e \in [e_{\min}, e_{\max}]$ is the exponent. For IEEE 754 double precision, $\beta = 2$, $t = 53$, $e_{\min} = -1022$, and $e_{\max} = 1023$. The significand is stored as a 52-bit fractional part, with the leading 1 bit implied by normalization, giving 53 bits of precision. The 11-bit exponent field encodes values from $-1022$ to $1023$ using a biased representation, and the 1 sign bit completes the 64-bit word.

A fundamental fact about this system is that the floating-point numbers are *not* uniformly distributed on the real line. They are dense near zero and sparse near $\pm\infty$, because the precision is relative rather than absolute. In any interval $[\beta^e, \beta^{e+1})$, there are exactly $\beta^{t-1}(\beta - 1)$ representable numbers, all equally spaced with gap $\beta^{e-t+1}$. This spacing, the distance between consecutive floating-point numbers near a given value $x$, is called the *unit in the last place* of $x$, written $\text{ulp}(x)$. The relative spacing is constant across all such intervals:

$$\frac{\text{ulp}(\beta^e)}{\beta^e} = \beta^{1-t}$$

This constant ratio defines *machine epsilon* $\varepsilon_{\text{mach}}$, the most important single quantity in numerical analysis. For IEEE 754 double precision, $\varepsilon_{\text{mach}} = 2^{-52} \approx 2.22 \times 10^{-16}$. Its operational meaning is the following sharp bound: for any real number $x$ within the representable range, the floating-point rounding operator $\text{fl}(x)$ satisfies

$$\text{fl}(x) = x(1 + \delta), \qquad |\delta| \leq \varepsilon_{\text{mach}}$$

This bound is the axiomatic foundation from which all error analysis in IEEE 754 arithmetic proceeds. It says that rounding introduces a *relative* error of at most $\varepsilon_{\text{mach}}$, regardless of the magnitude of $x$. Every operation, every intermediate result, every stored value introduces such a relative perturbation, and the whole art of numerical analysis is to understand how these perturbations interact as they flow through a computation.

Before that analysis can proceed, one must have precise definitions of error. Given a true value $x^*$ and a computed approximation $\hat{x}$, the *absolute error* is $|\hat{x} - x^*|$ and the *relative error* is $|\hat{x} - x^*| / |x^*|$, defined when $x^* \neq 0$. Neither concept is universally superior. Absolute error is natural when the magnitude of the result is fixed by the problem's physical units; relative error is natural when the result spans many orders of magnitude. In IEEE 754 arithmetic, the fundamental guarantee is on relative error, so relative error is usually the more illuminating quantity. However, relative error loses meaning near zero, which is why the behavior of floating-point subtraction near cancellation requires special attention.

## 2. Core Architecture & Mechanics

The 64-bit IEEE 754 double-precision layout arranges its three fields as follows, from most significant to least significant bit:

```
 63        62      52 51                                    0
  +--------+----------+--------------------------------------+
  |  sign  | exponent |             fraction                 |
  | 1 bit  |  11 bits |              52 bits                 |
  +--------+----------+--------------------------------------+
```

The exponent field stores a biased integer $E$ in $[0, 2047]$, with bias 1023, so the true exponent is $e = E - 1023$. The reserved values $E = 0$ and $E = 2047$ encode the system's special values. When $E = 0$ and the fraction field is zero, the value is $\pm 0$. When $E = 0$ and the fraction is nonzero, the value is a *subnormal* number: $\pm 0.\text{fraction} \times 2^{-1022}$. Subnormals extend the representable range below $2^{-1022}$ by sacrificing precision, providing *gradual underflow* rather than a sudden collapse to zero. When $E = 2047$ and the fraction is zero, the value is $\pm\infty$. When $E = 2047$ and the fraction is nonzero, the value is *NaN* (Not a Number), which propagates through subsequent operations to signal that a computation has produced a meaningless result.

The rounding rule IEEE 754 mandates by default is *round to nearest, ties to even*, also called banker's rounding. When the exact real-number result of an operation falls exactly halfway between two representable values, the result is rounded to whichever neighbor has a zero in its last significand bit. This breaks the systematic upward bias of the naive "round half up" rule. The standard specifies four additional rounding modes: toward $+\infty$, toward $-\infty$, toward zero, and round to nearest ties away from zero. The non-default modes are essential for interval arithmetic, where one deliberately rounds opposite endpoints in opposite directions to guarantee enclosure of the true result.

To see how errors propagate through basic arithmetic, consider the elementary floating-point operations one at a time. When two $t$-digit floating-point numbers $x$ and $y$ are added, the hardware aligns their exponents by right-shifting the significand of the smaller operand, then adds the aligned significands, then rounds the $(t + \text{guard})$-digit intermediate result back to $t$ digits. The IEEE 754 standard mandates that the hardware compute this as if it had infinite precision internally, then round once. The resulting absolute error in the sum is at most $\frac{1}{2}\text{ulp}(x + y)$, which translates into a relative error bounded by $\varepsilon_{\text{mach}}$.

For a chain of $n$ floating-point operations, errors accumulate. A classical first-order model for a sum $S = \sum_{i=1}^n x_i$ computed in left-to-right order uses the rounding model repeatedly. Each addition $s_k = s_{k-1} + x_k$ introduces a relative error bounded by $\varepsilon_{\text{mach}}$. By induction, the computed result $\hat{S}$ satisfies

$$\hat{S} = \sum_{i=1}^n x_i(1 + \delta_i), \qquad |\delta_i| \leq (n-1)\varepsilon_{\text{mach}}$$

to first order in $\varepsilon_{\text{mach}}$, with the precise bound being $(1 + \varepsilon_{\text{mach}})^{n-1} - 1 \leq (n-1)\varepsilon_{\text{mach}} + O(\varepsilon_{\text{mach}}^2)$. This estimate is pessimistic in practice, since rounding errors can cancel, but it provides a rigorous worst-case guarantee. The relative error in the sum grows linearly with $n$ in the worst case, which is why numerical analysts worry about long summations when $n$ is large.

The concept of a *condition number* formalizes how much error amplification a problem inherently admits, independent of any particular algorithm. For a function $f : \mathbb{R} \to \mathbb{R}$, the condition number at a point $x$ measures how much a small relative perturbation in the input is amplified into a relative perturbation in the output:

$$\kappa_f(x) = \left| \frac{x f'(x)}{f(x)} \right|$$

This follows directly from the first-order Taylor expansion: if the input $x$ is perturbed to $x(1 + \epsilon)$, then $f(x(1+\epsilon)) \approx f(x) + \epsilon x f'(x)$, so the relative change in the output is approximately $\epsilon \cdot |xf'(x)/f(x)|$. When $\kappa_f(x)$ is large, the problem is *ill-conditioned*: even perfect arithmetic produces a large relative error in the output because the input data themselves have only limited relative accuracy. When $\kappa_f(x)$ is small, the problem is *well-conditioned*. The condition number is a property of the mathematical problem, not of the algorithm. A large condition number cannot be overcome by a clever algorithm; it is a statement about the problem's inherent sensitivity to its inputs.

For linear systems $Ax = b$, the condition number generalizes to the matrix condition number

$$\kappa(A) = \|A\| \cdot \|A^{-1}\|$$

for any consistent matrix norm. When the 2-norm is used, this equals $\sigma_{\max}(A) / \sigma_{\min}(A)$, the ratio of the largest to smallest singular values. For a system with condition number $\kappa(A)$, a relative perturbation $\epsilon$ in the right-hand side $b$ leads to a relative perturbation in the solution $x$ of at most $\kappa(A) \cdot \epsilon$. This estimate is sharp in the worst case. A matrix with $\kappa(A) \approx 10^{12}$ in double precision, where $\varepsilon_{\text{mach}} \approx 10^{-16}$, leaves at most $16 - 12 = 4$ correct decimal digits in the solution, regardless of how the system is solved.

Forward and backward error analysis are two complementary frameworks for assessing the accuracy of computed results, and understanding their relationship is essential. *Forward error analysis* tracks how errors propagate from input to output through the sequence of arithmetic operations, bounding the absolute or relative error in the final result directly. It is rigorous but often technically laborious for complex algorithms, because one must carry error bounds through every intermediate step, and the bounds can be excessively pessimistic when intermediate cancellations reduce the actual error well below the worst case.

*Backward error analysis*, introduced by James Wilkinson in the 1950s and developed into a systematic methodology in his 1963 monograph *Rounding Errors in Algebraic Processes*, takes the opposite view. Rather than asking "how far is the computed result from the true result of the given problem?", it asks "what is the nearby problem for which the computed result is the exact solution?" The computed output $\hat{x}$ of an algorithm applied to input data $d$ is said to have backward error $\eta$ if there exists a perturbed data set $\hat{d}$ with $\|\hat{d} - d\| / \|d\| \leq \eta$ such that $\hat{x}$ is the exact solution of the problem with data $\hat{d}$. An algorithm is *backward stable* if its backward error is bounded by a modest multiple of $\varepsilon_{\text{mach}}$, say $O(n\varepsilon_{\text{mach}})$ for an $n$-dimensional problem.

The power of backward stability becomes apparent when it is combined with the condition number. If an algorithm is backward stable with backward error $\eta$, and the problem has condition number $\kappa$, then the forward error in the computed result is bounded by approximately $\kappa \cdot \eta$. For a backward stable algorithm applied to a well-conditioned problem, this gives a small forward error. For an ill-conditioned problem, even the best backward stable algorithm will produce a large forward error, but backward stability guarantees that the blame lies entirely with the ill-conditioning of the problem, not with the algorithm. This separation of concerns, isolating algorithmic behavior from problem sensitivity, is Wilkinson's central conceptual achievement.

## 3. High-Performance Optimization & Failure Modes

Catastrophic cancellation is the most dramatic and practically consequential failure mode in floating-point arithmetic, and it arises not from rounding in any single operation but from the structure of the computation itself. When two nearly equal quantities are subtracted, their leading significant digits cancel, and the result inherits the absolute errors of the two operands in full, with no leading digits to absorb them. The relative error of the result can be orders of magnitude larger than the relative errors of the inputs.

Consider the subtraction $f(x) = \sqrt{x+1} - \sqrt{x}$ for large $x$. As $x \to \infty$, $f(x) \to 0$, but the two operands $\sqrt{x+1}$ and $\sqrt{x}$ are both large and nearly equal. In double precision, each is computed with relative error at most $\varepsilon_{\text{mach}}$, so each has absolute error of roughly $\varepsilon_{\text{mach}} \cdot \sqrt{x}$. After subtraction, the absolute error in the result is still approximately $2\varepsilon_{\text{mach}} \cdot \sqrt{x}$, but the true value is $f(x) \approx 1/(2\sqrt{x})$. The relative error in the computed result is therefore approximately

$$\frac{2\varepsilon_{\text{mach}} \cdot \sqrt{x}}{1/(2\sqrt{x})} = 4\varepsilon_{\text{mach}} \cdot x$$

which grows without bound as $x \to \infty$. For $x = 10^{14}$, this gives a relative error near 1, meaning essentially all significant digits are lost. The remedy is algebraic reformulation: multiply and divide by the conjugate expression to obtain

$$f(x) = \frac{(\sqrt{x+1} - \sqrt{x})(\sqrt{x+1} + \sqrt{x})}{\sqrt{x+1} + \sqrt{x}} = \frac{1}{\sqrt{x+1} + \sqrt{x}}$$

This equivalent form involves no subtraction of nearly equal quantities. The denominator is large when $x$ is large, the numerator is exactly 1, and the result is computed to full relative precision. The mathematical identity is exact; the difference in numerical behavior is entirely due to the avoidance of cancellation.

A second classical example is the quadratic formula. Given $ax^2 + bx + c = 0$ with $b > 0$ and $b^2 \gg 4ac$, the root

$$x_1 = \frac{-b + \sqrt{b^2 - 4ac}}{2a}$$

suffers catastrophic cancellation because $\sqrt{b^2 - 4ac} \approx b$ and the numerator is a difference of two nearly equal large quantities. The numerically stable reformulation computes the well-conditioned root first:

$$x_2 = \frac{-b - \sqrt{b^2 - 4ac}}{2a}$$

and then recovers $x_1$ from Vieta's formula $x_1 x_2 = c/a$, giving $x_1 = c/(a x_2)$. This avoids the cancellation entirely by computing $x_1$ as a ratio rather than a difference.

The Kahan compensated summation algorithm addresses the accumulation of rounding errors in long summations without the catastrophic cancellation inherent in naive sequential summation. The algorithm maintains a *compensation variable* $c$ that accumulates the low-order bits lost in each addition:

$$y_i = x_i - c, \qquad t_i = S_{i-1} + y_i, \qquad c_i = (t_i - S_{i-1}) - y_i, \qquad S_i = t_i$$

The key insight is that $c_i$ captures the numerical error in the step $S_{i-1} + y_i$, specifically the low-order bits of $y_i$ that were lost when $y_i$ was added to the much larger partial sum $S_{i-1}$. This correction is fed into the next iteration, so errors are not accumulated but continuously corrected. The resulting bound on the absolute error in the final sum is $O(\varepsilon_{\text{mach}}) \sum_i |x_i|$, independent of $n$, compared to $O(n\varepsilon_{\text{mach}}) \sum_i |x_i|$ for naive summation. The Kahan algorithm requires four floating-point operations per summand rather than one, but it is indispensable in applications, such as long time integrations in ordinary differential equations, where the linear error growth of naive summation is unacceptable.

Fused multiply-add (FMA) is a hardware instruction, available on all modern processors conforming to IEEE 754-2008, that computes $a \cdot b + c$ in a single operation, with a single rounding at the end rather than two sequential roundings. The mathematical ideal is that $\text{fma}(a, b, c) = \text{fl}(a \cdot b + c)$, where $a \cdot b$ is computed exactly internally to full double-precision significand width before being added to $c$ and rounded. The benefit is both accuracy and speed: accuracy because the product $a \cdot b$ has $2t - 1$ significant bits before rounding, so combining it with $c$ before rounding avoids the loss of the low-order half; speed because the operation executes in a single instruction pipeline stage. FMA is the foundation of high-performance matrix multiplication algorithms, polynomial evaluation via Horner's method, and dot product computations in linear algebra libraries such as BLAS. For polynomial evaluation, Horner's method applied to $p(x) = \sum_{k=0}^n a_k x^k$ as the nested form $p(x) = a_0 + x(a_1 + x(a_2 + \cdots + x \cdot a_n))$ uses FMA to compute each step $r \leftarrow r \cdot x + a_k$ with a single rounding, achieving a backward error bound of $O(n\varepsilon_{\text{mach}})$ times the coefficient magnitudes.

Interval arithmetic provides a systematic alternative to point-precision floating-point analysis when rigorous guarantees are required. Rather than representing a quantity by a single floating-point number, interval arithmetic represents it by a closed interval $[a, b]$ of machine numbers such that the true value is guaranteed to lie within $[a, b]$. Operations on intervals are defined to preserve this containment: the sum of $[a_1, b_1]$ and $[a_2, b_2]$ is $[a_1 + a_2, b_1 + b_2]$, with the lower endpoint rounded downward and the upper endpoint rounded upward, exploiting the IEEE 754 directed rounding modes. The result is an interval guaranteed to contain the true sum. By chaining such operations, one obtains a rigorous enclosure of the true result of any computable expression, with no assumptions about cancellation or error correlation. The cost is interval widths that can grow rapidly for long computations, a phenomenon called the *dependency problem* when the same uncertain variable appears multiple times in an expression and the interval method treats each occurrence as an independent uncertainty. Affine arithmetic and Taylor model arithmetic are more sophisticated variants that track correlations and suppress the dependency problem, at greater implementation cost.

The practical workflow for a numerical analyst confronting a new computation begins with a condition number estimate. If $\kappa$ is large relative to $\varepsilon_{\text{mach}}^{-1}$, the computation is fundamentally limited by the precision of the input data, and no algorithmic improvement can recover the lost digits. One must either reformulate the problem to remove ill-conditioning, work in higher precision, or accept the inherent loss. If $\kappa$ is modest, the next question is whether the algorithm is backward stable. Gaussian elimination with partial pivoting is backward stable for most matrices encountered in practice, with a backward error of $O(n^3 \varepsilon_{\text{mach}})$ times the norm of the original matrix. The QR factorization via Householder reflections is backward stable unconditionally, making it preferable for least-squares problems where the normal equations would square the condition number. Iterative refinement, in which the residual of a computed solution is itself solved approximately and added back as a correction, can recover lost digits when higher precision is available for the residual computation, exploiting the fact that the correction step solves a well-conditioned perturbation of the original system.

Understanding these mechanics at the level of individual bits and rounding modes is not pedantic precision for its own sake. It is the foundation on which every reliable numerical algorithm is built. The gap between a computation that produces 15 correct digits and one that produces 3 is usually not a question of hardware speed or software optimization; it is a question of whether the algorithm's designer understood IEEE 754 arithmetic, recognized where cancellation would occur, and chose formulas that avoided it. The theorems of backward error analysis transform this understanding from an art of experience into a science of provable guarantees, and that transformation is the central contribution of numerical analysis to applied mathematics.
