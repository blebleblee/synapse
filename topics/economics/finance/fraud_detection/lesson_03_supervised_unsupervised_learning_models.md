# Lesson 3: Supervised, Unsupervised Learning Models for Fraud Detection

## 1. First-Principles Intuition & Invariants

Fraud detection in financial systems operates as a perpetual adversarial game between the institution's defensive statistical models and adaptive adversaries who continuously probe for weaknesses in detection boundaries. Unlike static classification problems where the underlying data-generating process remains stable, financial fraud exhibits non-stationary behavior: fraudsters learn from detection outcomes, adapt their attack vectors, and deliberately engineer transactions to mimic legitimate behavioral patterns. This adversarial drift imposes a fundamental constraint on model lifecycle management that distinguishes fraud detection from conventional supervised learning applications.

The central challenge emerges from extreme class imbalance. In typical retail banking transaction streams, fraud rates hover between 0.1% and 2% of total volume, creating a needle-in-haystack problem where the minority class carries asymmetric economic significance. A false negative—failing to flag a fraudulent wire transfer of $50,000—imposes direct loss on the institution, while a false positive—freezing a legitimate corporate payroll transaction—generates customer friction, operational overhead in manual review queues, and potential reputational damage. The cost matrix governing Type I and Type II errors is rarely symmetric, and optimal decision boundaries must be calibrated against business-specific tolerance thresholds rather than abstract statistical metrics like overall accuracy.

Feature engineering for fraud detection requires domain-specific transformation of raw transactional data into discriminative signals that capture behavioral deviation. Transaction amount alone provides limited signal; fraudsters deliberately structure transactions below reporting thresholds or mimic historical spending patterns. Instead, effective features encode velocity metrics—such as the number of distinct merchants contacted within a rolling 24-hour window—geographic anomaly indicators like impossible travel (a card used in New York at 2 PM and Singapore at 3 PM), session fingerprint changes (device ID or IP geolocation shifts), and peer cohort comparisons that measure how far a given user's behavior deviates from their historical baseline or similar customer segments.

Supervised learning models ingest labeled historical data where each transaction carries a binary ground-truth label: fraudulent or legitimate. The model learns a decision boundary in feature space that separates these classes, then applies this boundary to score incoming real-time transactions. Logistic regression provides a linear baseline with interpretable coefficient weights, but financial fraud patterns often exhibit non-linear interaction effects—for instance, a $500 transaction at a luxury retailer may be benign for a high-net-worth individual but anomalous for a budget-conscious student account. Tree-based ensemble methods like gradient boosted decision trees (XGBoost, LightGBM) excel at capturing these interaction effects through recursive feature splits, while neural networks offer maximal representational capacity at the cost of reduced interpretability.

Unsupervised learning complements supervised approaches by detecting novel fraud patterns that lack labeled training examples. Clustering algorithms like DBSCAN or Gaussian Mixture Models partition transaction space into dense regions of normal behavior, flagging outliers that fall in sparse regions as potential fraud. Autoencoders, a neural network architecture trained to reconstruct input transactions through a compressed latent representation, learn to encode normal transactional structure; transactions that yield high reconstruction error signal deviation from learned patterns. These unsupervised signals provide early warning of emerging fraud typologies before sufficient labeled data accumulates for supervised retraining.

Model interpretability carries operational necessity beyond regulatory compliance. When a fraud analyst reviews a flagged transaction, they require actionable explanations: which specific features triggered the alert, and how do those features compare to the customer's historical baseline? SHAP (SHapley Additive exPlanations) values decompose individual prediction scores into per-feature contribution metrics, enabling analysts to rapidly validate whether algorithmic flags align with investigative intuition. Counterfactual explanations answer the question: what minimal change to the transaction would have avoided the fraud flag? If the model flags a $1,200 transaction but indicates that reducing the amount to $800 would clear the threshold, this suggests the decision boundary may be miscalibrated.

Adaptive learning mechanisms address the temporal drift inherent in adversarial environments. Static models trained on historical data degrade in performance as fraudsters shift tactics. Continuous retraining pipelines ingest newly labeled fraud cases, but labels arrive with delay—manual review queues may take 24-72 hours to confirm fraud, and chargebacks from card networks arrive weeks after the transaction. Online learning algorithms update model parameters incrementally as new labels arrive, avoiding the computational expense of full batch retraining. Active learning strategies prioritize manual review resources by selecting the most informative uncertain cases for labeling, maximizing model improvement per human annotation hour.

The detection system must balance precision and recall under economic constraints. High precision (few false positives) minimizes operational review costs but allows more fraud to slip through. High recall (catching all fraud) floods review queues with false positives. Financial institutions set operating points on the precision-recall curve by estimating the break-even threshold: the expected fraud loss prevented must exceed the marginal cost of manual review. For high-value wire transfers, institutions tolerate lower precision to achieve near-perfect recall; for low-value point-of-sale transactions, automated approval with sampling-based audits becomes economically rational.

## 2. Core Architecture & Mechanics

The supervised learning pipeline for fraud detection begins with raw transactional event streams ingested from payment processors, card networks, and internal core banking systems. Each transaction record contains structured fields: merchant category code (MCC), transaction amount, timestamp, cardholder account identifier, merchant identifier, authorization response code, and optionally enriched geolocation data. Feature engineering transforms these raw attributes into discriminative signals through temporal aggregation windows, deviation metrics, and cross-account behavioral embeddings.

Temporal aggregation features compute rolling statistics over user-specific transaction history. A velocity counter tracks the number of transactions initiated within the past hour, six hours, and 24 hours, capturing burst patterns characteristic of compromised credentials used in rapid succession. Average transaction amount over the past 30 days establishes a personal spending baseline; the current transaction's z-score relative to this distribution quantifies deviation magnitude. Time-since-last-transaction measures dormancy, as accounts inactive for months suddenly reactivated often signal account takeover. These features require stateful computation: a streaming feature store maintains per-account aggregates, updating them incrementally as new transactions arrive while expiring stale data outside the window.

Geographic anomaly detection constructs features from IP geolocation, billing address, and merchant location triangulation. Impossible travel flags occur when consecutive transactions imply physically impossible movement—a card swiped in Los Angeles followed 30 minutes later by an online purchase geolocated to Moscow. Distance-from-home calculates great-circle distance between transaction location and the cardholder's registered address, with transactions beyond a 500-mile radius assigned higher risk weight. Cross-border transaction indicators flag currency mismatches or high-risk jurisdiction codes maintained by compliance teams. These features require geospatial enrichment services that map IP addresses and merchant IDs to latitude-longitude coordinates, then compute haversine distances.

Peer cohort comparison features measure how a transaction deviates from similar users' behavior. Demographic segmentation groups users by account age, average balance, transaction frequency tier, and primary merchant category usage. For each cohort, the system computes median transaction amount, 95th percentile amount, and typical merchant diversity. The current transaction's percentile rank within its cohort provides a normalized deviation score. Graph-based features encode transactional network topology: if multiple accounts suddenly begin transacting with the same obscure merchant within a short window, this cluster pattern may indicate a coordinated fraud ring testing stolen card credentials.

Supervised classification models ingest these engineered features as input vectors. Logistic regression fits a linear decision boundary by maximizing log-likelihood of observed labels under a Bernoulli distribution assumption. The model learns coefficient weights $\beta$ such that the fraud probability $P(y=1|\mathbf{x}) = \sigma(\beta^T \mathbf{x})$, where $\sigma$ denotes the logistic sigmoid function. Coefficient interpretation reveals feature importance: a large positive weight on the impossible-travel indicator directly quantifies its contribution to fraud probability. However, logistic regression assumes feature independence and cannot capture interaction effects like "high transaction amount is suspicious only if combined with new merchant."

Gradient boosted decision trees address non-linearity through sequential ensemble construction. The algorithm initializes with a constant prediction (the base fraud rate), then iteratively adds weak learners—shallow decision trees—that correct residual errors from the previous ensemble. Each tree partitions feature space through recursive binary splits: at each node, the algorithm selects the feature and threshold that maximally reduce Gini impurity or cross-entropy loss in child nodes. For instance, the root split might separate transactions above and below $1,000; the left child node then splits on merchant category, while the right splits on velocity count. Final predictions aggregate leaf scores across all trees. Gradient boosting handles missing values natively, automatically learns feature interactions, and provides feature importance rankings through split frequency and gain metrics.

Neural network architectures offer maximal flexibility for learning complex decision boundaries. A feedforward network stacks multiple fully connected layers with non-linear activation functions (ReLU, tanh). The first hidden layer projects input features into a learned embedding space where linear separability improves; subsequent layers refine this representation. Training proceeds via backpropagation: the algorithm computes prediction error (binary cross-entropy loss), propagates gradients backward through the network using the chain rule, and updates weights via stochastic gradient descent or adaptive optimizers like Adam. Regularization techniques—dropout randomly zeros neuron activations during training, L2 weight decay penalizes large weights—prevent overfitting to the imbalanced training set.

Handling class imbalance requires specialized training procedures. Naïve training on raw data yields a degenerate model that predicts "legitimate" for all transactions, achieving 99% accuracy but zero recall on fraud. Cost-sensitive learning assigns asymmetric misclassification penalties: the loss function applies a weight multiplier of 50 to 100 for false negatives, forcing the model to prioritize fraud recall. SMOTE (Synthetic Minority Over-sampling Technique) generates synthetic fraud examples by interpolating between existing fraud cases in feature space, though this risks overfitting to training data artifacts. Undersampling randomly discards legitimate transactions to balance the training set, trading reduced training set size for improved class balance.

Unsupervised anomaly detection models learn the structure of legitimate transactions without relying on fraud labels. Isolation Forest constructs random decision trees that recursively partition feature space; anomalies require fewer splits to isolate into singleton partitions, yielding shorter average path lengths. DBSCAN clusters transactions by density: points with at least $k$ neighbors within radius $\epsilon$ form dense clusters, while points failing this criterion are labeled outliers. One-class SVM fits a hyperplane that encloses the majority of training data; new transactions falling outside this boundary are flagged as anomalous.

Autoencoder neural networks learn compressed representations through an encoder-decoder architecture. The encoder network projects input transactions into a low-dimensional latent space (e.g., 32 dimensions), while the decoder attempts to reconstruct the original input from this bottleneck representation. Training minimizes reconstruction loss (mean squared error) on legitimate transactions. At inference time, fraudulent transactions that deviate from learned patterns yield high reconstruction error, as the autoencoder fails to accurately reconstruct novel behavioral patterns. Variational autoencoders extend this framework by learning a probabilistic latent distribution, enabling probabilistic anomaly scoring through likelihood estimation.

Model deployment requires real-time scoring infrastructure with strict latency constraints. Payment authorization flows impose sub-100-millisecond response time requirements to avoid degrading customer experience at checkout. Feature stores pre-compute and cache temporal aggregates, updating them asynchronously as background processes to avoid blocking critical path computation. Model servers load trained model artifacts into memory, expose RESTful APIs for scoring requests, and horizontally scale across multiple instances for load distribution. For ultra-low-latency requirements, models are compiled into optimized inference engines (ONNX Runtime, TensorFlow Lite) that execute on bare-metal hardware rather than containerized Python runtimes.

Threshold calibration translates continuous fraud scores into binary approval decisions. The precision-recall curve plots the trade-off achieved by sweeping the decision threshold from 0 to 1. The optimal operating point depends on business-specific cost parameters: expected fraud loss per transaction, cost per manual review, and customer friction cost per false positive. If fraud losses average $2,000 per incident, manual reviews cost $5, and false positive friction costs $10, the break-even threshold satisfies the condition where marginal fraud prevention value equals marginal review cost. Institutions often maintain multiple thresholds: an upper threshold for automatic decline, a lower threshold for automatic approval, and a middle band routing transactions to manual review queues.

## 3. High-Performance Optimization & Failure Modes

Performance optimization for fraud detection models begins with feature selection to reduce dimensionality and eliminate redundant or low-signal features. Correlation analysis identifies highly correlated feature pairs; retaining only one from each pair reduces multicollinearity without sacrificing predictive power. Recursive feature elimination trains models on progressively smaller feature subsets, ranking features by their marginal contribution to validation set AUC. Features exhibiting temporal instability—high importance during training but zero importance on recent holdout data—signal concept drift and should be retired. Reducing the feature set from 200 to 50 dimensions decreases inference latency, shrinks model memory footprint, and improves model interpretability.

Hyperparameter tuning optimizes model architecture and training parameters through systematic search. Grid search exhaustively evaluates all combinations of candidate hyperparameters (tree depth, learning rate, regularization strength), while Bayesian optimization models the validation performance surface and intelligently samples high-promise regions. For gradient boosted trees, key hyperparameters include maximum tree depth (controls model complexity), learning rate (scales contribution of each tree), and subsample ratio (fraction of training data used per tree). Cross-validation with temporal splitting—training on months 1-6, validating on month 7, testing on month 8—ensures hyperparameters generalize across time rather than overfitting to a single historical snapshot.

Ensemble methods combine multiple models to improve robustness and reduce variance. A stacked ensemble trains a meta-model (often logistic regression) on predictions from base models (gradient boosting, neural network, isolation forest). Each base model captures different aspects of fraud patterns; the meta-model learns optimal weights to combine their signals. Averaging predictions from models trained on different random subsamples of data (bagging) reduces overfitting. Ensembles that blend supervised and unsupervised signals (e.g., multiplying XGBoost fraud probability by autoencoder reconstruction error) capture both labeled historical patterns and novel anomalies lacking training data.

Addressing adversarial drift requires continuous monitoring of model performance degradation. Fraud detection teams track daily precision and recall metrics, plotting them on time-series dashboards to detect sudden performance drops. Population stability index (PSI) quantifies distributional shift in feature values between training and production data; PSI exceeding 0.1 signals significant drift requiring model retraining. Individual feature importance drift—a feature moving from rank 5 to rank 30 in importance—indicates fraudsters have adapted to exploit that signal. Automated retraining pipelines trigger when PSI exceeds thresholds or when precision drops below acceptable bounds, ingesting recent labeled data and redeploying updated models.

Explainability techniques address the black-box nature of complex models. SHAP values decompose individual predictions into per-feature contributions by computing Shapley values from cooperative game theory. For a transaction flagged with 0.85 fraud probability, SHAP might attribute +0.30 to impossible travel, +0.20 to velocity spike, and -0.10 to merchant familiarity. These attributions enable fraud analysts to validate model reasoning and identify cases where the model focuses on spurious correlations. LIME (Local Interpretable Model-agnostic Explanations) fits a local linear approximation around the prediction, offering simpler but less theoretically grounded explanations. Counterfactual generation identifies the minimal feature changes required to flip the prediction, answering "what if" questions for manual investigators.

False positive reduction optimizes the precision side of the trade-off. Manual review queues become bottlenecks when flooded with low-quality alerts; analysts develop alert fatigue and miss genuine fraud cases. Precision-focused training adjusts classification thresholds or loss functions to prioritize clean signals over maximum recall. Multi-stage pipelines route low-confidence predictions to automated rules (e.g., "if customer has 5+ years tenure and transaction matches historical pattern, auto-approve") while escalating high-confidence anomalies to human review. Active learning prioritizes review queue cases where model uncertainty is highest (predictions near 0.5), as these provide maximal information gain for model retraining.

Scalability challenges emerge when deploying models across millions of accounts and billions of transactions. Feature computation for temporal aggregates requires distributed stream processing frameworks (Apache Flink, Kafka Streams) that partition accounts across worker nodes and maintain in-memory state stores for aggregates. Model serving infrastructure horizontally scales across GPU-accelerated inference servers for deep learning models or CPU-optimized servers for tree ensembles. Caching strategies store precomputed feature vectors for high-frequency accounts, invalidating cached values only when new transactions update aggregates. Partitioning strategies route high-risk accounts or geographic regions to dedicated model variants specialized for those segments.

Regulatory compliance imposes constraints on model deployment and documentation. The Equal Credit Opportunity Act prohibits using protected attributes (race, gender, age) as direct features, but proxy features (ZIP code, merchant preferences) may inadvertently encode these attributes. Disparate impact analysis measures whether fraud detection disproportionately flags transactions from protected groups; models exhibiting significant disparate impact require justification and mitigation. Model documentation must record training data provenance, feature definitions, hyperparameters, validation methodology, and performance metrics for audit purposes. GDPR right-to-explanation requirements mandate human-interpretable justifications for automated decisions affecting EU customers.

Adversarial robustness testing probes model vulnerabilities to deliberate manipulation. Fraudsters may intentionally structure transactions to evade detection boundaries—splitting large purchases into multiple small transactions below velocity thresholds, or mixing fraudulent transactions with legitimate activity to pollute behavioral profiles. Red team exercises simulate adversarial strategies, measuring model performance under evasion attacks. Adversarial training augments the training set with synthetic adversarial examples, forcing the model to learn robust decision boundaries. Game-theoretic frameworks model the fraud detection system as a two-player game, deriving equilibrium strategies that remain optimal even under adaptive adversaries.

Cold start problems arise for new accounts lacking historical transaction data. Feature-based models relying on temporal aggregates produce uninformative scores when velocity counters remain at zero and baseline spending distributions lack samples. Transfer learning leverages patterns learned from existing accounts, initializing new account risk scores based on cohort averages or demographic similarities. Cautious default policies apply conservative thresholds to new accounts, gradually relaxing restrictions as transaction history accumulates and confidence in behavioral models increases. Graph-based models propagate risk scores across social networks, flagging new accounts created by users linked to known fraudsters.

The detection system must maintain operational resilience under component failures. Feature store outages degrade model input quality; fallback strategies revert to simplified rule-based detection using only transactional metadata available in real-time. Model server failures require request routing to backup instances or graceful degradation to previous model versions. Monitoring systems track end-to-end latency distributions, alerting on p99 latency spikes that indicate scoring infrastructure strain. Circuit breakers automatically disable underperforming models, reverting to ensembles excluding the failing component until the issue resolves. These failure modes demand rigorous testing under realistic production load, simulating database partitions, network latency spikes, and cascading service dependencies.
