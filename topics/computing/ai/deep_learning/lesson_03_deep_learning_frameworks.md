# Lesson 3: Deep Learning Frameworks and Libraries

## 1. First-Principles Intuition & Invariants

A deep learning framework is best understood as a specialized runtime and compiler system for differentiable tensor programs. At its core, a neural network is a composition of affine transformations, nonlinear activations, normalization operations, convolutions, attention mechanisms, and other tensor-valued functions. The framework's job is to represent that composition in a way that is executable on heterogeneous hardware, differentiable with respect to its parameters, and efficient enough to train models containing billions of parameters. For senior engineers and systems architects, the most important mental model is that TensorFlow, PyTorch, and Keras are layered abstractions over the same fundamental substrate: tensors, kernels, memory allocators, schedulers, and communication libraries.

The first invariant is tensor semantics. A tensor is an N-dimensional array with a shape, a data type, a device placement, and a memory layout. Shape determines the number of elements and the valid index space. Data type determines the arithmetic precision and the range of representable values. Device placement determines whether the tensor resides in host memory, GPU memory, accelerator memory, or a distributed shard. Memory layout determines how elements are ordered in physical memory, which in turn affects cache locality, vectorization, and kernel performance. A framework that violates these invariants produces subtle bugs: silent shape mismatches, dtype promotion errors, device synchronization failures, and memory corruption.

The second invariant is differentiability. Modern training relies on reverse-mode automatic differentiation, which computes gradients by traversing the computation in reverse topological order and applying the chain rule. For this to work, the framework must record enough information during the forward pass to reconstruct the gradient of each operation. In eager systems such as PyTorch, this is typically done through an autograd tape that records operations as they execute. In graph-based systems such as TensorFlow, the graph itself encodes the forward computation, and gradient kernels are derived from the graph structure. In both cases, the invariant is that every trainable parameter must have a well-defined gradient path, and every non-differentiable operation must be explicitly marked or handled.

The third invariant is memory lifetime. Deep learning workloads allocate and free large tensors continuously: activations, gradients, optimizer states, temporary buffers, and communication buffers. The framework must ensure that tensors are not freed while kernels are still reading them, that GPU memory is not double-freed, and that host-to-device copies are synchronized correctly. This is where systems programming discipline becomes essential. A Python-level tensor object may be garbage collected, but the underlying device memory may still be referenced by an asynchronous kernel. Frameworks therefore use reference counting, arena allocators, CUDA streams, and synchronization primitives to preserve memory safety.

The fourth invariant is concurrency. Training is inherently concurrent: CPU threads prepare batches, GPU threads execute kernels, communication threads exchange gradients, and data loader workers read from storage. The Python Global Interpreter Lock does not prevent concurrency at the C++ and device level, but it does constrain how Python-level parallelism is expressed. A framework must therefore expose asynchronous execution, stream-based scheduling, and thread-safe tensor operations. When these mechanisms are misused, the result is not merely slowness, but deadlock, race conditions, and nondeterministic behavior.

TensorFlow, PyTorch, and Keras occupy different points in the abstraction space. TensorFlow was historically built around static computation graphs, where the program is traced into a graph before execution. This design enables aggressive optimization, graph partitioning, and deployment to constrained devices. Modern TensorFlow also supports eager execution, but its production strength remains in graph-based execution, XLA compilation, and distributed serving. PyTorch was built around eager execution and dynamic control flow, making it the dominant research framework. Its autograd tape is constructed at runtime, allowing Python control flow, dynamic shapes, and rapid experimentation. PyTorch’s production path now includes TorchDynamo, TorchInductor, and distributed training libraries that compile and optimize eager programs without sacrificing flexibility. Keras is a higher-level API for building, training, and evaluating models. It abstracts away much of the tensor-level detail and provides a consistent model-building language. In its modern form, Keras can run on TensorFlow, JAX, or PyTorch backends, making it a portable model definition layer rather than a single runtime.

The practical consequence of these design choices is that TensorFlow, PyTorch, and Keras are not interchangeable in all contexts. TensorFlow excels when the model is stable, the graph is large, and deployment targets include mobile, edge, and serving infrastructure. PyTorch excels when the model is evolving, the control flow is dynamic, and the research loop must be fast. Keras excels when the goal is to express a model architecture clearly, train it with a standard loop, and move it across backends with minimal code changes. A senior architect must choose based on the lifecycle stage of the model, the hardware topology, the deployment target, and the operational constraints of the training cluster.

## 2. Core Architecture & Mechanics

The internal architecture of a deep learning framework can be decomposed into five layers: the Python API, the tensor and operation layer, the execution engine, the automatic differentiation engine, and the hardware kernel layer. The Python API provides the user-facing objects: tensors, modules, optimizers, datasets, and training loops. The tensor and operation layer defines the algebra of tensors and the semantics of operations such as matrix multiplication, convolution, softmax, and layer normalization. The execution engine schedules operations, manages memory, and coordinates host and device execution. The automatic differentiation engine records forward operations and computes gradients. The hardware kernel layer contains the actual CPU and GPU implementations, often generated from libraries such as cuBLAS, cuDNN, oneDNN, and NCCL.

A tensor is more than a multidimensional array. It is a handle to a memory buffer with metadata. The metadata includes shape, stride, dtype, device, and, in some frameworks, a version counter for in-place operations. Strides determine how many elements must be skipped in memory to move one index position along each dimension. A contiguous tensor has a stride of 1 in all dimensions, while a non-contiguous tensor has a stride greater than 1 in one or more dimensions.

The tensor and operation layer is responsible for defining the algebra of tensors and the semantics of operations. This includes defining the rules for tensor multiplication, convolution, and other operations, as well as the rules for handling non-differentiable operations. The execution engine is responsible for scheduling operations, managing memory, and coordinating host and device execution. This includes managing the execution of kernels, handling memory allocation and deallocation, and synchronizing host and device execution.

The automatic differentiation engine is responsible for recording forward operations and computing gradients. This includes recording the operations performed during the forward pass, as well as computing the gradients of each operation with respect to the model parameters. The hardware kernel layer contains the actual CPU and GPU implementations, often generated from libraries such as cuBLAS, cuDNN, oneDNN, and NCCL.

In summary, a deep learning framework is a complex system that requires careful design and implementation to ensure that it meets the invariants of tensor semantics, differentiability, memory lifetime, and concurrency. Each layer plays a critical role in ensuring that the framework meets the invariants and provides a robust and efficient platform for deep learning.
