# Lesson 2: Core Architecture & Memory Subsystems

## 1. Process, Threading & Concurrency Architecture

In the realm of systems programming, understanding the architecture of processes, threads, and concurrency is foundational. Processes and threads are the fundamental units of execution in modern operating systems, each serving distinct roles in the management of system resources and the execution of tasks. Processes are isolated units of execution that contain their own memory space, including code, data, and stack segments. This isolation ensures that a failure in one process does not affect others, enhancing system stability and security. Threads, on the other hand, are lightweight units of execution that share the same memory space within a process. This shared memory allows threads to communicate and synchronize more efficiently than processes, which must use inter-process communication (IPC) mechanisms.

The Linux kernel employs a sophisticated scheduling mechanism known as the Completely Fair Scheduler (CFS) to manage the execution of processes and threads. CFS is a preemptive, priority-based scheduler that aims to provide fair CPU time allocation among all runnable tasks. At its core, CFS uses a red-black tree data structure to maintain a sorted list of tasks based on their virtual runtime (`vruntime`). The `vruntime` of a task is a measure of the amount of CPU time it has consumed relative to its priority. Tasks with lower `vruntime` values are given higher priority, ensuring that no single task monopolizes the CPU. The scheduler periodically recalculates the `vruntime` of each task, taking into account the task's priority and the time it has spent running, to maintain fairness.

The isolation and coordination of processes and threads are achieved through a combination of hardware and software mechanisms. In the Linux kernel, processes are isolated using namespaces, which provide a mechanism to isolate global system resources such as the process ID (PID) namespace, the network namespace (Net), the mount namespace (Mount), the IPC namespace (IPC), the UTS namespace (UTS), and the user namespace (User). Each namespace creates a separate view of the system resources, allowing processes to operate in isolated environments. Threads, sharing the same memory space, are coordinated using synchronization primitives such as mutexes, semaphores, and condition variables, which ensure that shared resources are accessed in a controlled and predictable manner.

The Linux kernel also employs a mechanism known as the `infra/pause` container to anchor container runtimes. The `infra/pause` container is a lightweight container that serves as the root namespace for other containers, providing a consistent environment for containerized applications. Container runtimes such as Docker and containerd use Linux control groups (cgroups) to manage resource limits and allocate resources such as CPU, memory, and network bandwidth to containers. Cgroups provide a hierarchical structure for resource management, allowing administrators to set limits and priorities for individual containers and groups of containers.

## 2. Memory Subsystems & Buffer Management

The memory subsystem of an operating system is a critical component that manages the allocation, access, and deallocation of memory resources. In the Linux kernel, memory is organized into pages, which are fixed-size blocks of memory typically ranging from 4KB to 64KB. The virtual memory subsystem uses multi-level page tables (PML4/PML5) to map virtual addresses to physical addresses, allowing processes to access memory in a virtualized and isolated manner. The page tables are organized in a hierarchical structure, with each level of the table containing entries that point to the next level of the table until the final level, which contains entries that point to physical frames of memory.

The Translation Lookaside Buffer (TLB) is a hardware cache that stores recent translations from virtual addresses to physical addresses, reducing the overhead of address translation. When a process accesses a memory address, the TLB is consulted first to determine if the translation is already cached. If the translation is not found in the TLB, the page tables are traversed to find the corresponding physical address, and the translation is then cached in the TLB for future access. The TLB is periodically invalidated to ensure that stale translations are not used, which can occur when a process is terminated or when memory pages are swapped out to disk.

Page faults occur when a process attempts to access a memory page that is not currently loaded into physical memory. When a page fault occurs, the kernel handles the fault by loading the missing page from disk into physical memory and updating the page tables to reflect the new mapping. The kernel also employs various page replacement algorithms to manage the limited physical memory available to the system. Common page replacement algorithms include the Least Recently Used (LRU) algorithm, which evicts the page that has not been accessed for the longest time, and the Clock algorithm, which uses a circular list to track page usage and evicts pages based on a reference bit.

Buffer management is another critical aspect of the memory subsystem, particularly in the context of I/O operations. Buffers are used to temporarily store data that is being read from or written to disk, reducing the overhead of frequent disk I/O operations. The Linux kernel employs a buffer cache to manage buffers, which stores frequently accessed data in memory to improve I/O performance. The buffer cache uses a least recently used (LRU) algorithm to manage the limited buffer space available, evicting buffers that have not been accessed for the longest time.

Shared memory segments are another mechanism used to manage memory in the Linux kernel. Shared memory allows multiple processes to access the same memory segment, enabling efficient communication and synchronization between processes. Shared memory segments are created using the `shmget` system call, which allocates a shared memory segment and returns a shared memory identifier. Processes can then attach to the shared memory segment using the `shmat` system call, which maps the shared memory segment into the process's address space. Shared memory segments can be detached using the `shmdt` system call and destroyed using the `shmctl` system call.

## 3. Data Structures & On-Disk Binary Layouts

Understanding the layout of data structures and on-disk binary formats is essential for systems programmers and engineers who need to work with low-level system resources. Data structures are used to organize and manage data in memory, while on-disk binary formats are used to store data on persistent storage devices such as hard disks and solid-state drives.

One of the most common data structures used in the Linux kernel is the linked list. Linked lists are used to manage dynamic data structures such as the process list, the task list, and the file descriptor table. A linked list consists of a series of nodes, each containing a data element and a pointer to the next node in the list. Linked lists are efficient for dynamic data structures because they allow elements to be inserted and deleted without requiring the entire list to be reallocated.

Another common data structure used in the Linux kernel is the hash table. Hash tables are used to manage data structures that require fast lookup, insertion, and deletion operations. A hash table consists of an array of buckets, each containing a linked list of elements. Elements are inserted into the hash table by computing a hash value based on the element's key and using the hash value to determine the bucket in which the element should be stored. Hash tables are efficient for fast lookup operations because they allow elements to be accessed in constant time on average.

On-disk binary formats are used to store data on persistent storage devices such as hard disks and solid-state drives. The Linux kernel uses various on-disk binary formats to store data, including the ext4 file system, which uses a combination of bitmaps, inodes, and block groups to store file system metadata and data.
