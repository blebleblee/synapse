# Lesson 2: Core Architecture & Memory Subsystems

## 1. Process, Threading & Concurrency Architecture

In the realm of computing, the execution of programs is abstracted through processes and threads, which are the fundamental units of work managed by the operating system kernel. Processes represent independent instances of a program, each with its own memory space, while threads are lightweight units of execution that share the same memory space within a process. Understanding how these entities are scheduled, isolated, and coordinated is crucial for systems programmers and engineers aiming to build efficient and scalable software.

At the heart of process management lies the scheduler, which determines the order in which processes and threads are executed on the CPU. In Linux, the Completely Fair Scheduler (CFS) is the default scheduler, designed to provide fairness and efficiency in process scheduling. CFS operates on the principle of maintaining a red-black tree of runnable tasks, where each task is assigned a virtual runtime (`vruntime`). The task with the smallest `vruntime` is selected for execution, ensuring that tasks with shorter execution times are not starved by longer-running tasks. This mechanism is complemented by preemption models that allow the scheduler to interrupt running tasks and switch to other tasks, thereby maintaining responsiveness and fairness.

Thread management introduces additional complexity due to the shared memory space among threads within a process. This shared memory allows threads to communicate and share data efficiently, but it also necessitates mechanisms to ensure data consistency and prevent race conditions. In Linux, threads are implemented using the POSIX Threads (pthreads) library, which provides a standardized interface for creating and managing threads. The `pthread_create` function initializes a new thread, while `pthread_join` waits for a thread to complete its execution. Thread synchronization is achieved through mutexes, semaphores, and condition variables, which help manage access to shared resources and coordinate thread execution.

The isolation of processes and threads is achieved through the use of namespaces and control groups (cgroups). Namespaces provide a mechanism to isolate system resources, such as the process ID (PID) namespace, which allows each process to have its own unique set of process IDs. The network namespace isolates network interfaces and routing tables, while the mount namespace isolates file systems. Cgroups, on the other hand, provide a way to limit and account for resource usage, such as CPU, memory, and disk I/O, ensuring that processes do not consume excessive resources and affect system performance.

Coordination among processes and threads is facilitated through inter-process communication (IPC) mechanisms. Common IPC methods include pipes, message queues, shared memory, and semaphores. Pipes allow unidirectional communication between processes, while message queues provide a way to send and receive messages. Shared memory segments enable multiple processes to access the same memory region, facilitating efficient data exchange. Semaphores are used to synchronize access to shared resources, preventing race conditions and ensuring data consistency.

## 2. Memory Subsystems & Buffer Management

The memory subsystem is a critical component of the operating system, responsible for managing the allocation, access, and deallocation of memory resources. Understanding the memory hierarchy, page layouts, cache hierarchies, and buffer management techniques is essential for optimizing performance and ensuring efficient memory usage.

At the highest level, the memory hierarchy consists of the CPU cache, main memory (RAM), and secondary storage (disk). The CPU cache is a small, fast memory located on the CPU chip, designed to store frequently accessed data and instructions. It is organized into multiple levels, with L1, L2, and sometimes L3 caches, each with different sizes and access speeds. The cache hierarchy is managed through a combination of hardware and software mechanisms, including cache coherence protocols and cache replacement algorithms.

Cache replacement algorithms determine which data to evict from the cache when it is full. Common algorithms include Least Recently Used (LRU), Least Frequently Used (LFU), and First In, First Out (FIFO). The choice of replacement algorithm can significantly impact cache performance, as it affects the hit rate and miss rate. In modern CPUs, hardware prefetching and adaptive replacement policies are used to improve cache performance by predicting and loading data into the cache before it is explicitly requested.

Main memory, or RAM, is a volatile memory that stores data and instructions that are currently being used by the CPU. It is organized into pages, which are fixed-size blocks of memory. The page size is typically 4 KB, but it can vary depending on the architecture. The operating system uses a page table to map virtual addresses to physical addresses, allowing processes to access memory using virtual addresses without being aware of the underlying physical memory layout. The page table is stored in main memory and is updated by the operating system whenever a page is loaded or evicted from memory.

Page faults occur when a process attempts to access a memory page that is not currently in main memory. When a page fault occurs, the operating system loads the missing page from secondary storage into main memory and updates the page table to reflect the new mapping. The process of handling page faults involves several steps, including identifying the missing page, loading it from disk, updating the page table, and resuming the execution of the process. Efficient page fault handling is crucial for maintaining system performance, as it minimizes the overhead of loading pages from disk.

Buffer management is another critical aspect of memory subsystems, particularly in the context of I/O operations. Buffers are used to temporarily store data during I/O operations, reducing the number of I/O operations required and improving performance. The operating system uses buffer caches to store frequently accessed data, such as file system metadata and frequently read/written data. Buffer caches are managed using replacement algorithms, such as LRU, to ensure that the most recently used data is retained in memory.

## 3. Data Structures & On-Disk Binary Layouts

Understanding the layout of data structures and on-disk binary formats is essential for systems programmers and engineers working with low-level system programming. Data structures are used to organize and manage data efficiently, while on-disk binary layouts define how data is stored and retrieved from secondary storage.

Data structures are typically defined using a combination of arrays, linked lists, trees, and graphs. Arrays provide a simple and efficient way to store and access data using contiguous memory blocks. Linked lists, on the other hand, consist of nodes that are linked together using pointers, allowing for dynamic memory allocation and efficient insertion and deletion of elements. Trees, such as binary search trees and red-black trees, provide a hierarchical organization of data, allowing for efficient searching, insertion, and deletion. Graphs are used to represent complex relationships between data elements, such as social networks and web graphs.

On-disk binary layouts define how data is stored and retrieved from secondary storage. The layout of data on disk is critical for efficient data access and retrieval, as it affects the performance of I/O operations. Common on-disk binary formats include fixed-length records, variable-length records, and indexed files. Fixed-length records store data in fixed-size blocks, allowing for efficient random access. Variable-length records store data in blocks of varying sizes, allowing for more efficient storage of data with variable lengths. Indexed files use a combination of indexing and caching to improve data access and retrieval.
